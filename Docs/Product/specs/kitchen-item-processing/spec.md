## Purpose

定义合作厨房内物品、容器、空间动作、加工与份数的目标行为，让玩家能够分工交接半成品而不复制或丢失实物。规格依据已确认及授权补足规则捕获；本轮备料子集与完整目标分开，样机碗容量 1、两作业各 60 Tick，正式容量与时间仍未平衡。

## Requirements

### Requirement: 唯一实物身份与单槽

物品 MUST 具有唯一运行身份和实际位置；普通手槽与台面一格一物，容器及其内部内容随同一容器移动。容器是同一物件的能力，不另建可独立消费的物件副本；禁止双重位置、循环包含和无定义无限堆叠。

#### Scenario: 交给他人一只装料碗
- **WHEN** 玩家将装料碗放到台面供另一玩家拾取
- **THEN** 同一碗及内容一起移动，原手槽不再占有它，不能留下第二份材料

### Requirement: 空间交互与预览同规则

玩家 MUST 点击格子自动寻路并四方向逐格移动；新目标在当前一步完成后替换路线与旧互动。玩家可穿行，每格最多两人停驻，满格在最后合法停点等待空位。普通台面 MUST 仅四邻格互动，点击自动转向，远处目标自动接近后执行一次。场景点击与 UI 选择 MUST 使用同一默认动作、目标 ID 和完整预检，拒绝时保留物品，不自动换目标。画面与地图输入按已确认的竖屏、2D、正对地图边俯视 45°、正交和整体纵向拖动规则实现。

#### Scenario: 预览后目标被占用
- **WHEN** 放置预览合法，但执行前另一玩家占用了目标槽
- **THEN** 拒绝该次放置，物品仍在原手槽，不偷偷改放另一处

### Requirement: 角色退出与意外落物

断线 MUST 保留逻辑成员、撤销绑定角色的未执行意图，将手持物放在 Host 最后提交格并移除角色。显式 Leave 同样收尾实物。地面物品 MUST 不阻挡路线，同格可保留多个独立 ItemId；空手且仅同格可选择拾取一个，不自动合堆。

#### Scenario: 两人同格断线后队友拾取
- **WHEN** 两名持物玩家在同格断线，队友来到该格选择其中一个 ItemId
- **THEN** 仅所选物品进入队友手槽，另一个仍留地面，容器内容随原物品移动

### Requirement: 动作完整预检后提交

拾取、放下、添加、取出、开始加工、倾倒、盛装、提交、清空、丢弃及绑定类动作 MUST 完整核对兼容、容量、锁定、占用和业务资格后原子提交。错误原料不得先扣除再补偿；失败保持所有受影响物品与进度。

#### Scenario: 投入不兼容原料
- **WHEN** 材料不被当前容器或配方阶段接受
- **THEN** 不移走源材料，不改变容器内容，不创建加工结果

### Requirement: 手工持续参与与自动加工分离

手工加工 MUST 点击开始，由单一工作者持续参与；点击停止、移动、离开或交接中断并保留进度、释放认领，无需持续长按。一工位同时一个加工，不允许双人加速同一工作。设备自动加工按业务时钟推进，不自动搬运、装料或服务顾客。该加工输入为已确认目标，当前格子样机不实现加工。

#### Scenario: 玩家接续别人未做完的工作
- **WHEN** 原工作者停止并释放认领，新工作者合法接手
- **THEN** 从已有进度继续，不重置、不复制加工，也不让两名工作者同时推进

### Requirement: 配方阶段与结果身份

配方 MUST 由实际投入和阶段状态推导，并在显式开始后加工；步骤依赖必须满足。切割消耗输入并创建新中间物件；需要保留输入到倾倒时的容器加工不能提前生成可消费成品。指定番茄蛋花汤开始后不可取消，移动锅不停止自动加工。

#### Scenario: 移动正在煮汤的锅
- **WHEN** 番茄蛋花汤已经显式开始加工且锅被搬动
- **THEN** 加工继续，输入保持锁定，尚不能取料或盛装完成结果

### Requirement: 批次盛装守恒

批次 MUST 明确剩余份数，成功盛装一次源减一份且目标增一份；最后一份只成功一次并按配方消费输入、复位容器。目标满、不兼容或不可达时源目标都不变；存放、搬运、换关不补满批次。整份倾倒与完成批次逐份盛装须保持各自语义。

#### Scenario: 两人争取最后一份
- **WHEN** 两个合法盛装请求争用只剩一份的源批次
- **THEN** 仅一个成功，另一个明确失败，不产生两份成品

### Requirement: 锁定、清空与丢弃

已开始锁定的输入 MUST 禁止随意取出或清空；完成批次不能加料、移除输入或再次启动。允许处理时须持物到对应设施四邻：液体仅向水池排放，固体仅向垃圾桶倾倒，不允许随时随地清空/丢弃。清内容保留容器身份、位置和脏净；嵌套容器不连带销毁，丢弃不默认删锅或设备，不退款、回库、加分或生成结果。

#### Scenario: 清空剩余成品
- **WHEN** 玩家持允许处理且未锁定的成品容器，到对应水池或垃圾桶合法倾倒
- **THEN** 剩余份数和内容消失，容器仍在原处，不将材料恢复到供应池

#### Scenario: 设施与内容不匹配
- **WHEN** 玩家持固体向水池请求清空，或在未到对应设施时发起丢弃
- **THEN** 明确拒绝且保留物品/内容，不原地销毁或自动换一个清理目的地

### Requirement: 水池接水与排液分开

水池 SHALL 支持向定义兼容的干净空容器接水，并处理合法液体内容。接水形成属于原容器的真实水物件，核对容量/占用；排液保留原脏净而不代替洗碗。Solo 子集已实施，当前烹饪默认供水不因设施增加自动变成显式加水步骤。

#### Scenario: 真实水内容与满容器
- **WHEN** 玩家持合法空容器到水池接水，随后满容器再次接水
- **THEN** 首次产生一份属于该容器的水，第二次拒绝并保留内容，不先清空再补水

### Requirement: 代表汤的合作制作链

番茄蛋花汤 MUST 支持番茄直接切块生成新中间物、不增加洗菜步骤；手持碗即可手工打蛋，不需要工位。蛋液入锅腾出碗，番茄入锅，默认水不占物品容量；在灶台显式启动自动煮制，到点后锅为完成态且输入仍留锅中，盛装时才形成独立汤物件。餐具有限，制作碗可复用为盛汤碗，回收洗净后再用。

#### Scenario: 制作与交付由不同玩家完成
- **WHEN** 一人完成锅内加工，另一人用合法空碗盛汤并交付
- **THEN** 生成独立汤物件并消耗对应批次，订单完成只发生于合法提交，锅中完成不等于已交付

#### Scenario: 手持制作碗打蛋
- **WHEN** 玩家手持已合法放入鸡蛋的碗并开始打蛋
- **THEN** 无需占用工位即可持续手工作业，完成后得到适用蛋液，倒入锅后同一碗可继续用于盛汤
