## 已落成的后续 change（2026-10-13）

用户已授权把此前九个方向与工程建议由浅到深写成正式 change。当前路线统一见[由浅到深的 change 路线](change-roadmap.md)：14 个新规划案，复用既有消息边界、合作核心、前厅、清理供应与双 Editor 案。这里不再复制任务计数或依赖图；最新实施状态查原 tasks/execution-notes。

规划不等于实施授权。UI 结构、表驱动行为、测试夹具维护分别成案；所有选定功能先在 Editor 验收，PC Player/LAN 和 Android 真机放在最后。Solo 与合作分别记录，不能用共享代码或单机通过推断远端通过。

### 已确认决定

- Solo 首个大关三关结束，不发终关装修、不建第四关；保存大关完成记录后返回选档。完成记录可查看，另选新开建立新运行。
- 首饮为鲜榨橙汁，真实切橙与榨汁；加工期间锁定果汁壶，完成后可搬走逐杯分装，产量和耗时由配置决定。本轮用户已明确采用这组首版规则。
- 合作装修由 Host 选择，队友查看；首版只开放已有新增工位奖励。
- 原成员恢复首版只做本次运行内手动恢复，不包含程序重启后的身份恢复。
- Android 后台自动暂停，回前台仍暂停，手动继续；系统结束程序后读取最后成功检查点。

具体产量、耗时、各关来客与评分数值仍属配置和平衡工作，不把“由配置决定”解释成已经确定数值。饮品 Solo 与合作适配已分别建案：[first-drink-order-binding](../../openspec/changes/first-drink-order-binding/proposal.md)、[cooperative-drink-order-binding](../../openspec/changes/cooperative-drink-order-binding/proposal.md)。

### 联机长期进度仍是独立缺口

当前合作路线面向内存餐厅。若目标是“联机继续某个档／保存共同进度”，还需细化 Save Owner、载入授权、写入和中断返回方式；Host 不自动是 Save Owner。单机保存代码可复用，不代表这些权限合同成立。

合作装修、内存成员恢复和 LAN 试玩不强依赖联机存档，也不得宣称长期合作经营已完成。联机三关终点与持久恢复仍分别保留；本次 Solo 三关确认不自动扩展到联机。

### 后续案的交接要求

各案声明目标模式、真实前置、状态 owner、发送/接收和退出责任。已有完整且行为未变的证据直接引用；新动作、新消息、新文件格式或实际缺口补最小相关验收。新玩家理解由实际试玩观察，脚本不能代替。

“已实现／已验收／仍缺什么”回填[根进度](../../CarzyCooker当前进度.md)的对应模式行。协议生成、共有 Hotfix 和任务勾选不替代运行证据；设备/提交/第二工作区操作仍按各自执行授权。
