# 合作餐厅操作说明

Solo选档和合作房间“选择章节”各提供家常开张、进阶小馆、蒸茶小馆三个内容章，每章三小关。蒸茶小馆第一关有牛肉蒸饺和热红茶，第二关增加冰鲜奶茶，第三关增加珍珠奶茶；下面的蒸饺/茶饮步骤适用于这一章，材料、器具和有限批次连续承接，原料不足按原有限补货取得。

Solo按原“保存并继续”发布成功检查点，第三关“保存完成并返回选档”，完成记录只读；另选新开建立独立餐厅。合作由Host发布同章提案、全员准备并开局，各关结果按原个人领取流程保存；终关由Host“完成大关并返回房间”，在原房间重新提案准备可独立复玩。终关无装修或第四关，零星仍正常成功；旧两章有效记录保持原Next与库存，不补蒸食/茶饮物资。当前运行范围见[主题章执行记录](../../openspec/changes/archive/2026-10-17-restaurant-themed-chapter/execution-notes.md)。

“补货总览”选择来源后可“请求1包”，每人一条，可替换或撤销；发布只沟通，不采购。任意原本可采购的成员明确点“处理请求…（采购1包）”，才按原配额、菜单和阶段采购，不需Host审批。只有实际预留成功才显示“已下单”，可“查看请求”跳原货物；失败仍待处理，可修正条件后重试。两人竞争处理只采购一次，普通独立采购不自动处理请求；请求退出/换关清理，原货物仍继续运输并需明确接收、拆份。

在“工位说明”选择真实工位/餐桌，或在“物品查找”选择实物后，可点“标记工位／餐桌／物品”。地图紫色文字和“查看标记 · 成员…”指出发送者与目标；查看只回原详情/高亮，不移动或认领。每人一个，新标记替换本人旧值，可“取消我的目标标记”；10个业务秒到期、暂停冻结。物品标记随同一物品拿放，消费后消失；退出/失联、换关清理，恢复不重放，关闭HUD或恢复页不保留旧派生标记。

在具体订单的“制作”说明里，可点“我准备制作此单（不独占）”或“撤销我的制作意向”。每人同时一条，改选替换自己的旧意向；同单可显示多人，其他成员仍可正常制作、贴单和交付。查看订单不发意向请求，暂停时只读；订单结束、成员失联/退出或换关会清理，手动恢复后需重新选择。

主页、单机选档和餐厅可打开“本机设置”，选择标准/较大/大号文字、慢/标准/快地图拖动、三类经营提醒和3/5/10业务秒临期阈值。“保存本机设置”成功后应用；“取消本机设置”只丢弃未保存草稿，“恢复设置默认”仍需明确保存。设置不暂停餐厅、不改其他成员或进度文件，拖动仍不点击；保存失败保留原值。大字下动作区可滚动到底，关闭后回原页面；设置在本机重进保留。经营提醒已接入，操作见下文。

“前厅动作”中的“营业总览”按需求、客流、得分查看本关事实。需求只统计待交付订单，已贴单杯和预制成品不抵扣；展开菜品后选择具体顾客可进入原制作说明并返回。客流包含进场占队列、被物占用空桌和满队列跳过说明，可转原前厅工作看板。得分展示真实门槛，过程参考不会提前结算；完成后使用原权威星级并可转原结算。查看不发动作，暂停冻结期限，失联/恢复与换关后需重新选择。

自然完成后可点“本关复盘”，查看各菜已交付、超时和实际得分贡献；未询问和跳过来客不算订单，超时不倒扣。复盘只读本关、不保存历史；“复盘：返回结算”回原页面，仍需明确选择装修、保存或下一关。Client可查看与Host相同的结果，原控制权限保持；零星仍可继续。

主页、房间和合作餐厅增加“合作待领”数量入口，只统计本机已持久化且仍可领取的结果；未查询、查询中和失败分别显示。领取页可切换全部/可领取/已领取/已关闭并“查看结果”，阅读不新建记录；明确“领取此结果”才提交。已领可“查看已领记录”，按Slot显示当前修订；空闲离线可“前往单机选档”进入原完整检查，明确确认前不开局，房间成员继续沿原权限查看或读取。取消等待不撤销已发布记录，重新查询确认实际状态；缺少身份资料时查询失败，后台不补建密钥或信任。

结算摘要集中显示结果、记录状态、下一步和目的地；“结算详情”可读原装修/保存说明及下关菜单的新增/移出，阅读和关闭不发经营命令。内存、保存中、失败和已提交分别说明，失败保留原结果可重试；个人已领取以“合作进度领取”查询为准。Host沿原按钮继续，Client只读等待；零星仍可继续，终关明确返回选档或房间，不生成第四关。

结算的装修候选现在先打开“装修预览”，按奖励类型说明新增、解锁、扩建或原工位升级；“取消装修预览”保留原候选，“确认此装修”才实际选定。升级比较的是不含本关加成的配置基础耗时，已开始作业继续使用自己的冻结耗时；安装类奖励仍在下一关完整预检。Client可“查看装修”，实际选择由Host确认；换关、重开或他端选定后旧预览失效。

“布局与装修”里的“工位说明”可通过工位条目只读查看；选中后露出地图，蓝色表示实际占地，绿色表示配置给出的候选操作格，可切换“查看详情”或隐藏标记。详情区分设备定义能力与本关匹配工序、所需容器；候选位置不保证实时可达，实际操作仍由原规则验证。Client可查看但无布局控制权。关闭说明或换关不保留旧标记，地图点击继续原拿放/行走规则。

“前厅动作”中的“前厅工作看板”按询问、清桌和洗碗查看真实任务、当前执行者与进度，满手也可阅读。查看不认领，接手/停手使用原按钮；前往途中停手仍需走完当前格步，再作新认领。收尾页解释已有顾客和必要工作，不要求清空后厨；换关或重开不沿用旧行。可以收起详情并切“全部动作”回到原制作。

厨房“补货动作”里的“补货总览”按来源查看外部余包、运输/待接收、已接收记录及真实包装内容，记录不是额外实物。采购、接收和拆份仍需逐次明确点击原按钮；收货台满时腾空后接收同一货物。包装查看只打开物品定位，不取料；暂停/收尾/结算可查看原限制，重开或换关会清理查看目标。

## 当前入口与动作导航（2026-10-16）

合作开局先由Host在章节／菜单预览点“发布房间提案”，或通过原成功记录／合法授权发布来源提案；此时不创建厨房或进度。房间显示共享提案版本、实际剩余菜单及每位成员状态，所有当前连接成员（含Host）分别点“准备本提案”，可点“取消准备”。全员准备后Host才能点“开始本轮餐厅”，不能强开。章节／菜单／来源修订、成员加入／离开／失联／恢复绑定变化会清空全部准备；餐厅退役后须重新发布和准备。显式Host启动也停在所选提案，不直接开局。Solo和进行中餐厅的加入／恢复不加准备门槛；来源原授权、身份和完整开局校验仍保留。

“伙伴互动”中，Solo玩家或Host可点小麦“岗位：自动（询问优先）／询问优先／洗碗优先”。自动沿用原询问优先；优先类别没有合法可用任务时仍处理另一原有类别。选择只改变下次空闲调度，不打断已认领、前往或工作，不重置进度和成长。准备、营业、收尾阶段未暂停时可选，暂停只读；合作Client查看同一已提交值，没有修改权限。偏好本轮连续关卡保留，关内成长仍重置；关闭后新开或从成功档新建运行恢复自动，不写进度文件。

本机选档先点记录完成检查，再用“编辑名称与收藏”输入别名、设置收藏，点“保存名称与收藏”才提交。“清空名称（草稿）”恢复默认名称，仍需保存；“取消名称编辑”丢弃未保存草稿。列表可点“收藏记录”筛选。名称最多32个Unicode文本元素，不含换行/控制字符；原记录ID、修订、来源和章节仍可查看。名称只属于本机此Slot，不改变成功进度、授权或其他设备；保存失败保留旧名并可重试。元数据损坏只影响名称/收藏，原有效进度仍可查看和继续；实际继续仍须原完整校验及修订确认。

营业中到货、加工完成或订单进入临期会更新“提醒 #序号 · 类别”入口；打开后只列最近8项，点“查看提醒”进入原物品、补货或具体订单查看，仍须自行执行原动作。已消费/离开的目标会提示已变化，不替你改选。首次进入和手动恢复仅建立当前基线，不补播过去事件；HUD重开不重复。各类默认开启，关闭会立即移除该类当前提醒，重新开启不补旧事件。临期默认剩余5个业务秒，可选3/5/10秒；暂停不减少期限，提醒不自动暂停或取货。

动作分类中的“物品查找”可按名称和材料／容器类别查看当前实物。选择结果会收起大详情区，并高亮当前外层宿主：容器内材料随容器定位，手持物随持物者定位，落物指向地面格。“查看详情”可展开脏净、加工锁定和宿主说明；物品消失后会明确提示。查找不计入在途货，也不会远程取物或移动角色。

有待处理订单时，可在菜谱分类或全部动作中点击“制作 · 餐桌 · 菜品”。目标区会列明顾客和餐桌，可切换“订单：完整菜谱／制作缺口”，或只读查看相关实物与工位后返回。选择订单不认领、不移动、不贴单、不交付；现有饮品仍按实际合法贴单解释。所选订单结束会清理目标并提示，HUD重开及换关不沿用旧选择。

准备阶段可打开“开店准备总览”，查看本关菜单、加成条件、开店控制和现有物资，并进入原菜谱、补货或布局分类。必选加成仍须原选择，暂停时须先恢复；没有预制成品不会阻止开店。Client只读并等待房主决定。开始营业、换关或关闭HUD后，本轮总览会退出。

单机记录列表可筛选“全部记录／可继续记录／已完成记录”。点击记录先完整读取并校验，再显示剩余份数、加工、工位和运输摘要；此时还没有创建餐厅。点“确认继续此记录”会重新读取文件，修订或结果身份变化时须重新核对后再确认。完成记录仅供查看；刷新保留仍有效的选择，损坏或取消不会改写原记录。

合作入口可“粘贴地址”，房主创建房间后可“复制加入地址”。复制的是当前实例实际监听地址；127.0.0.1只适用于同一电脑。跨电脑仍需原显式LAN启动，入口不会扫描网卡或测试防火墙。“连接帮助”可返回原入口，非法输入保留原文本供修改；正在加入时可取消，超时按原流程回到开始页后重新选择。

选择内容章或保留菜单后先阅读开局预览：Solo点“确认开始”，Host点“发布房间提案”，之后按上述共享准备流程开局。摘要列出实际关数与保存方式，滚动菜单按关列菜品；“返回开始方式／返回内容列表”只取消本端预览。Solo成功后按原规则新增记录，内存试玩退出不保留；合作仍由原领取／授权流程保存。Client可查看本端目录，Host发布后的房间提案才是共同准备的内容。

普通 Launcher 的主页提供单机餐厅、继续记录、合作房间、合作进度领取与存档授权。进入“合作房间”才显示创建／加入及地址输入；“返回开始页”回主页，不因此创建连接。房间内先“选择章节”查看内容章，或“菜单试玩”进入保留菜单链；返回房间首页只切页，不关闭房间。原Host开局请求现在须通过共享提案及全员准备门槛。

厨房动作列表上方提供全部动作、当前目标、厨房、菜谱、补货、前厅、布局装修和伙伴分类。分类只筛选已有合法按钮，不移动人物或发命令；当前选中工位的主要动作仍保留。点“全部动作”可找回完整入口，拖动仍只查看餐厅。暂停可查看分类，恢复、操作资格与工作进度仍由原规则决定。

本页后续段落保留早期批次操作与当时范围；当前独立 Player、升级、合作基线／领取等支持与未验收环境，以[根进度](../../CarzyCooker当前进度.md)及相应 change 的 execution-notes 为准。

## 早期批次范围

Host／Client 首版只支持本轮内存餐厅与回环 KCP；运行结果见三个 change 的 execution-notes，装修、成员恢复与饮品贴单新增链已在主端Host／第二端Client的真实双Editor通过。单机存档不作为联机存档。普通 Host 从饮品关卡 3 开始，随后关卡 4 可继续；旧两菜配置 1／2 保留给既有调用者。

## 装修

Host 选择本关加成并开店。自然结算后先等待装修候选准备，再选择一项新增工位或直接继续。Host 点“下一关”时先完整预检；位置被落物占用等失败会保留本关、选择和全部实物。Client 只能看同一候选、选择与已安装工位，不能选择、继续或调整。合作不列工位升级奖励，也不写个人检查点。

## 牛肉蒸饺

从“菜单试玩→开启蒸食餐厅”进入合作菜单，发布并全员准备后开局；Solo在选档页选择“新开蒸食餐厅”。切配一份洋葱，把洋葱块和牛肉末各一份加入拌馅盆，拿起盆点“组装 牛肉洋葱馅”；完成后放回台面，加入一份饺子皮，拿起点“组装 未熟牛肉蒸饺”。盆及半成品都可沿原拿放交接。

包好后把盆放回台面，点“查看详情→取出 未熟牛肉蒸饺”，把唯一未熟饺放入蒸锅，空手显式“蒸制”。完成后拿熟饺加入干净蒸食盘，再拿盘交付真实订单；未熟或没装盘不能交付。加工中锁定，暂停停钟；拌馅盆保留，蒸食盘走原清桌/洗碗流程。原料不足时可原采购有限的洋葱、牛肉末和饺子皮包装，不供应馅或熟饺。Solo/合作成功领取保留真实半成品和未完加工，旧菜单不补本批库存。

## 茶饮

Solo选择“新开茶饮餐厅”，合作在菜单试玩选择“开启茶饮餐厅”，发布提案并全员准备。直接拿空泡茶桶，到取水台热水档显式接一份热水，再放回加入一份红茶叶，空手显式泡茶，获得三份茶底。一份装热杯就是热红茶；另一份装调饮壶，加一份牛奶和一份糖浆，显式调饮得到两份奶茶基底。

生珍珠必须在煮珍珠台煮熟，可存入小料罐再取出。冰鲜奶茶按一份奶茶基底→一份冰装冷杯，再混合；珍珠奶茶按一份熟珍珠→一份奶茶基底→一份冰，再混合。错序不消耗，不能用生珍珠。三款均放茶饮贴单台绑定有效订单，再拿杯到对应桌交付。杯及内容一次消费，不进入洗碗池；原料、冰和杯按有限补货取得，基底不退款。

本批冷杯和调饮壶可在水池排液、在垃圾桶处理固体，保留另一物态和原壳；其他混合容器保持原限制。加工中锁定，暂停停钟；半杯、剩余基底和未完泡茶/煮珍珠可按原成功档或合作领取保存，恢复不补料、不恢复旧贴单。

## 橙汁与贴单操作

两端都可采购橙子与空杯，并在收货台接收、拆份。清理补货包装时先处理剩余内容，再丢空包装。把橙子放切配台，由任一成员切块，空手成员接取橙块并装入果汁壶。把壶放榨汁机，显式点榨汁；加工中锁壶与设备，完成后才可搬壶，每次向干净空杯盛一份。

把成品杯放贴单台，空手选择当前橙汁订单贴单。合法换绑一次替换原关系；错误或已占订单不会先解除旧关系。取杯走到对应餐桌并交付，原杯与饮品只消费一次。顾客离开后正常清桌，一次性杯不进入洗碗池。

## 本轮手动恢复

Client 失联后禁止玩法输入，HUD 显示“手动恢复”和“结束本地恢复”。点手动恢复会建立新 Session，凭本轮内存凭证接回原成员；取得本人确认、当前关完整投影与视图后才开放输入。恢复为空手，旧手持物已落在 Host 世界，可由他人接续，不能复制或自动取回。

结束本地恢复只清本地意图，反馈会明确“未向 Host 确认 Leave”。在线成功 Leave、整轮 Stop 或已收到 Host 关闭通知后不能用原凭证恢复。超时可能是回执未到，不代表请求未提交；可显式新尝试，不自动重放玩法动作。关闭重开 HUD 不创建新成员。两端进程重启、跨设备、自动重连和 Host 迁移均不在支持范围。
