# 快速开始

本页随main来源功能同步；其中玩法运行与历史Passed属于源记录，第二工作区本轮Unity／UTF／双Editor结果另行报告，尚未执行项保持NotRun。

> **ET 底座适用说明（2026-10-09）**：当前 ProcedurePreset 直接进入 ET；GameHot 源码、配置和 GF Network 运行时已移除。本文保留的 GameHot/纯 GF 示例与双模式切换段落仅作历史参考，不是当前可执行流程。ET、GF 公共组件与 HybridCLR 的适用部分仍以当前源码/配置为准。

本篇覆盖首次拉取、工具链编译、Unity 模式选择、编辑器运行和 ET 服务端启动。完成后再进入 UI、Entity、热更新或构建专题。

## 1. 环境要求

| 依赖 | 要求 | 用途 |
| --- | --- | --- |
| Unity | `6000.3.18f1` | 客户端与编辑器工具 |
| .NET SDK | 8.x | 服务端、导表、Proto、文件服务器 |
| MongoDB | 按需安装 | ET Demo 的持久化服务 |
| Odin Inspector | 商业授权 | 编辑器检查器与工具面板 |

Unity 的精确版本记录在 `Unity/ProjectSettings/ProjectVersion.txt`。版本不一致时，先确认 API 与资源序列化兼容性，不要直接升级工程。

## 2. 获取源码

仓库的 Luban 扩展是 Git Submodule。首次拉取或切换分支后执行：

```powershell
git submodule update --init --recursive
```

确认 `Tools/Luban/Luban-Extension` 已有内容，再继续编译。

## 3. 编译工具链

在仓库根目录执行：

```powershell
dotnet build Kit.sln
```

`Kit.sln` 包含服务端项目和共享工具。构建产物进入 `Bin/`，供导表、Proto 生成、文件服务器与 ET 服务端使用。

也可在 Unity 中打开 `Game/Build Tool Editor`，点击 `Build Kit.sln`。首次打开 Unity 前使用命令行构建更容易看到完整错误。

## 4. 打开 Unity

用 Unity Hub 打开 `Unity/`，等待脚本和资源导入完成。项目入口场景是 `Unity/Assets/Launcher.unity`，直接打开并按 Play，或点击工具栏上的 `Launcher`，默认进入 Solo 格子样机，显示地图与 HUD；无须先使用实例窗口。Game 视图选 9:16 可查看竖屏布局。示例台面只支持拿放，完整烹饪与订单尚未实施。

如果工具栏尚未出现，先等待编辑器完成编译，并确认 Console 没有编译错误。

### 显式实例启动

`Game/Multiplayer/Instance Launch` 使用同一 Launcher，显式提交 `runId`、`instanceId`、`role` 和对应 endpoint。标识只接受字母、数字、点、下划线、短横线；`role` 是 `legacy/solo/host/client`。Host 的 listen 省略时为 `127.0.0.1:0` 意图，Client 必须指定非零 loopback connect，legacy／solo 不接受 endpoint。切换角色时清空另一角色的 endpoint。

窗口草稿不影响运行中不可变配置；普通 Launcher 不继承草稿或上一轮请求，每轮默认建立 Solo 配置。只有显式 legacy 进入原 ET 示例。显式请求无效或 Editor 忙碌时拒绝；关闭 Scene Reload 的显式请求也拒绝，不修改 Play 选项。请求通过工程路径范围的 SessionState 跨正常 Play 域重载交接。

`Prepared` 仅表示配置已交接。普通 Launcher 默认 Solo，装载后合法 Solo/Host/Client 进入独立产品根；显式 legacy 保留旧入口。缺适用产品代码仍明确失败为 `ProductBootstrapUnavailable`，不回落 Demo。Solo 本地加入后报 SoloReady，Host 控制台报告实际非零 listen，再以本地 Joined 报 HostReady；Client 使用该实际 endpoint，须取得本人确认与名单才报 ClientReady。地图及 Board／HUD 就绪另报 GridReady。当前实际 CodeMode=ClientServer，仍为 Unity 原型；正式餐厅、产品存档和身份恢复尚未实施。

本地 Join/Probe/Leave 经过真实队列与 MailBox；远端为既有 UDP-KCP→Session→相同有序裁决。诊断可通过 Loader 的 ProductBootstrapBridge.Root 定位本轮 ProductRuntimeComponent，再从其 Client 使用 ProbeProduct/LeaveProduct；调用者消费并释放响应，不同步阻塞消息泵。UI 使用现有 owner，不增加业务状态副本。当前协议版本2、Probe最大1024 UTF-8 bytes、网络请求4秒、心跳2秒间隔/2秒预算；单独 Leave 不停止 Host，整体退出才收尾根。会话历史范围见 [产品执行记录](../openspec/changes/archive/2026-10-11-product-session-bootstrap/execution-notes.md)，地图与直接 Launcher 验收见 [地图执行说明](../openspec/changes/archive/2026-10-11-portrait-grid-kitchen-prototype/execution-notes.md)；双 Editor 新玩法和手机 Player 未验收。
