# 快速开始

合作进度的领取入口为房间或餐厅中的“合作进度领取”，模式选择页也可离线查询本机凭证。模式页“存档与授权”可离线浏览、导出和导入授权。开局前在房间“存档与身份”验证本机身份；需要对方身份时，主动交换并确认身份文件。没有本关开局资格的迟加入者从后续关卡开始参与领取。

自然完成一关后，Host 选择装修或明确“本关不选装修”，各端收到并持久化凭证后可主动“领取新档”。保存失败会保留资格，取消等待后可刷新查询真实提交；同一结果重复请求返回原记录。已领取档从原本机记录入口读取，创建新的餐厅运行。

Host 的“保存并继续”及终关“保存完成并返回房间”等待本机保存成功，队友没有领取不影响 Host 前进。“返回房间”仅退役餐厅，保留同一个 Match 的领取资格；从房间“返回模式选择”才正常结束整个 Match，按本机实际持久化的关闭回执关闭未领取资格，已领取记录保留。离线首版不保证跨设备全局一次，也不支持源 Owner 远程撤回已有分支。实现与运行记录见[合作结果领取](../openspec/changes/archive/2026-10-15-cooperative-result-claims/execution-notes.md)。

> **ET 底座适用说明（2026-10-09）**：当前 ProcedurePreset 直接进入 ET；GameHot 源码、配置和 GF Network 运行时已移除。本文保留的 GameHot/纯 GF 示例与双模式切换段落仅作历史参考，不是当前可执行流程。ET、GF 公共组件与 HybridCLR 的适用部分仍以当前源码/配置为准。

本篇覆盖首次拉取、工具链编译、Unity 模式选择、编辑器运行和 ET 服务端启动。完成后再进入 UI、Entity、热更新或构建专题。

## 1. 环境要求

| 依赖 | 要求 | 用途 |
| --- | --- | --- |
| Unity | `6000.3.18f1` | 客户端与编辑器工具 |
| .NET SDK | 8.x | 服务端、导表、Proto、文件服务器 |
| MongoDB | 按需安装 | ET Demo 的持久化服务 |
| Odin Inspector | 商业授权 | 编辑器检查器与工具面板 |

Unity 的精确版本记录在 `Unity/ProjectSettings/ProjectVersion.txt`。版本不一致时，先确认 API 与资源序列化兼容性，不要直接升级工程。

## 2. 获取源码

仓库的 Luban 扩展是 Git Submodule。首次拉取或切换分支后执行：

```powershell
git submodule update --init --recursive
```

确认 `Tools/Luban/Luban-Extension` 已有内容，再继续编译。

## 3. 编译工具链

在仓库根目录执行：

```powershell
dotnet build Kit.sln
```

`Kit.sln` 包含服务端项目和共享工具。构建产物进入 `Bin/`，供导表、Proto 生成、文件服务器与 ET 服务端使用。

也可在 Unity 中打开 `Game/Build Tool Editor`，点击 `Build Kit.sln`。首次打开 Unity 前使用命令行构建更容易看到完整错误。

## 4. 打开 Unity

用 Unity Hub 打开 `Unity/`，等待脚本和资源导入完成。入口场景是 `Unity/Assets/Launcher.unity`，直接按 Play 或点击工具栏 `Launcher`，先显示模式选择，无须实例窗口。“单机餐厅”进入原选档：选择“新开餐厅”、从记录继续或“内存试玩”，确认后显示地图与 HUD。“创建合作房间”显示实际监听地址，另一端填写该回环地址后选择“加入合作房间”；成员加入时可以没有餐厅，由 Host 点击“开启内存餐厅”。Host 返回房间后成员和连接保留，可以重开。Game 视图选 9:16 可查看竖屏布局；已落地范围见[当前进度](../CarzyCooker当前进度.md)。

PC合作房间的“存档与身份”可验证本机身份、浏览成功记录，再读取本人记录。使用他人记录时，双方主动交换“导出身份文件”，通过“查看导入文件”核对并确认公钥；Owner浏览自己的记录，为当前房主导出只读运行与本轮结果授权，房主查看该 `.ccrun` 文件并确认后载入。源文件保持原Owner及修订，当前加载不等于个人进度已保存。读取阶段可取消，开始建立世界后等待实际就绪。

如果工具栏尚未出现，先等待编辑器完成编译，并确认 Console 没有编译错误。

### 显式实例启动

`Game/Multiplayer/Instance Launch` 使用同一 Launcher，显式提交 `runId`、`instanceId`、`role` 和对应 endpoint。标识只接受字母、数字、点、下划线、短横线；`role` 是 `legacy/solo/host/client`。Host 的 listen 省略时为 `127.0.0.1:0` 意图，Client 必须指定非零 loopback connect，legacy／solo 不接受 endpoint。切换角色时清空另一角色的 endpoint。

窗口草稿不影响运行中不可变配置；普通 Launcher 不继承草稿或上一轮请求，每轮默认建立 Solo 配置。只有显式 legacy 进入原 ET 示例。显式请求无效或 Editor 忙碌时拒绝；关闭 Scene Reload 的显式请求也拒绝，不修改 Play 选项。请求通过工程路径范围的 SessionState 跨正常 Play 域重载交接。

`Prepared` 仅表示配置已交接。普通 Launcher 建立用于显示模式菜单的 Solo 配置；选择合作后经完整退出建立新的不可变 Host／Client 配置。模式菜单和单机选档浏览时没有运行餐厅，房间只显示成员与真实连接状态。显式 legacy 保留旧入口，显式 Solo／Host／Client 也保留原启动行为。缺适用代码明确失败为 `ProductBootstrapUnavailable`。Solo 本地加入后报 SoloReady；Host 报实际非零 listen，再以本地 Joined 报 HostReady；Client 取得本人确认与名单后报 ClientReady。地图及 Board／HUD 就绪另报 GridReady。当前 CodeMode=ClientServer；PC Solo 检查点只主动新建，不覆盖已有档。新模式入口已通过普通 Launcher 与同 Editor 真实 KCP 验收，Player/AOT 尚未验收。

本地 Join/Probe/Leave 经过真实队列与 MailBox；远端为既有 UDP-KCP→Session→相同有序裁决。诊断可通过 Loader 的 ProductBootstrapBridge.Root 定位本轮 ProductRuntimeComponent，再从其 Client 使用 ProbeProduct/LeaveProduct；调用者消费并释放响应，不同步阻塞消息泵。UI 使用现有 owner，不增加业务状态副本。当前协议版本见[当前进度](../CarzyCooker当前进度.md)、Probe最大1024 UTF-8 bytes、网络请求4秒、心跳2秒间隔/2秒预算；单独 Leave 不停止 Host，整体退出才收尾根。会话历史范围见 [产品执行记录](../openspec/changes/archive/2026-10-11-product-session-bootstrap/execution-notes.md)，地图与直接 Launcher 验收见 [地图执行说明](../openspec/changes/archive/2026-10-11-portrait-grid-kitchen-prototype/execution-notes.md)；双 Editor 完整合作餐厅已验收，见[集成记录](../openspec/changes/archive/2026-10-14-cooperative-restaurant-loopback/execution-notes.md)；手机 Player 未验收。

## 5. 选择客户端模式

模式开关位于 `Game/Define Symbol`。ET 与 GameHot 互斥，切换时工具会同步调整配置导出、资源规则、裁剪配置和 HybridCLR 设置。

| 目标 | 操作 |
| --- | --- |
| 纯 GF（GameHot） | 选择 `Add UNITY_GAMEHOT`（必选） |
| ET | 选择 `Add UNITY_ET` |
| 启用热更新 | 再选择 `Add UNITY_HOTFIX` |

切换后等待 Unity 重新编译。若菜单显示的是 `Remove ...`，表示对应符号已经启用。

`UNITY_GAMEHOT` 是纯 GF（GameHot）路线的必选符号；未启用 `UNITY_ET` 或 `UNITY_GAMEHOT` 时只会进入基础兜底流程，不会加载 GameHot 业务程序集。

## 6. 运行 ET Demo

1. 选择 `Game/Define Symbol/Add UNITY_ET`。
2. 打开 `ET/Build Tool`，将 `CodeMode` 设为 `ClientServer`。
3. 执行 `Game/Tool/ExcelExporter`，确保配置与当前模块一致。
4. 点击工具栏 `Launcher`。

`ClientServer` 会让 Unity 进程同时包含客户端与服务端代码，适合本地 Demo。只连接独立服务端时使用 `Client`；纯服务端裁剪验证可使用 `Server`。

## 7. 运行 GameHot Demo

1. 选择 `Game/Define Symbol/Add UNITY_GAMEHOT`。
2. 执行 `Game/Tool/ExcelExporter`。
3. 点击工具栏 `Launcher`。

GameHot 以 MonoBehaviour 工作流组织热更业务。入口为 `Game.Hot.Init`，加载后实例化 `Assets/Res/Hot/HotEntry.prefab` 并启动自己的 Procedure。

## 8. 独立启动 ET 服务端

先完成 `dotnet build Kit.sln` 和 ET 配置导出。服务端配置位于 `Config/Luban`，运行目录必须是 `Bin/`，因为 `ConfigReader` 使用相对路径读取 `../Config/Luban`。

```powershell
Push-Location Bin
dotnet App.dll --AppType=Watcher --StartConfig=Localhost --Console=1
Pop-Location
```

Watcher 会读取 `StartMachineConfig` 与 `StartProcessConfig`，为本机启动匹配的 ET 进程。只调试单个进程时可使用 `--AppType=Server --Process=<进程Id>`。

停止 Watcher 前，确认其子进程也已退出。若场景使用数据库，启动前应确保 MongoDB 地址与 `StartZoneConfig` 一致。

## 10. 首次运行排错

### 找不到 `Tool.exe` 或 `FileServer.dll`

重新执行 `dotnet build Kit.sln`，并检查 `Bin/`。Unity 菜单只是调用这里的构建产物。

### ET 提示未设置 CodeMode

打开 `ET/Build Tool`，选择 `Client`、`Server` 或 `ClientServer`。该选择对应 `UNITY_ET_CODEMODE_*` 编译符号。

### 配置或生成代码缺失

执行一次 ExcelExporter。模式切换会改变 `Design/Excel/ET/luban.conf` 与 `Design/Excel/GameHot/luban.conf` 的 `active` 状态，生成物应与当前模式一致。

### Unity 编译后仍没有 Launcher

检查 Package Manager 是否成功安装 `me.xw.toolbarextension`，再查看 Console 中最早出现的编译错误。

同平台分支转交：Owner 在本机记录中选择“导出分支许可”，接收者在“存档与授权”查看 `.ccbranch`、核对并确认签发身份，再“导入为独立分支”。确认前可取消；导入后产生接收者自己的记录，可从单机选档继续，不再依赖原 Owner 在线，也不改源档。ReadRun 的 `.ccrun` 不能用于导入。

需要有损覆盖时，从未领取结果选择“选择有损替换”，核对目标 Owner、Slot 和当前修订后“确认有损替换”。本人目标直接选择；其他 Owner 先为指定接收身份和来源根签发 `.ccreplace`，本机必须已有该目标。目标有变化须取得当前修订的许可并重新确认；失败可重试，成功保留目标 Owner，丢弃旧进度且不留恢复备份。重复请求只返回当时的领取位置和修订，不恢复已被后续覆盖的旧内容。见[导入与替换记录](../openspec/changes/archive/2026-10-15-save-branch-import-and-replace/execution-notes.md)。

首批沙拉可从单机选档“新开沙拉餐厅”，或Host房间“开启沙拉餐厅”进入。切番茄、生菜和黄瓜后，把番茄块/生菜片/黄瓜片各一份放入同一干净盘；F02另加一份芝士片。拿盘明确选择对应“组装”，缺料/多料拒绝且不消耗；开始后可停止、搬运并由队友拿原盘接续。三种蔬菜不会自动变成F01，未完成不能交付。盘容量四份，完成成品仍独占一盘，原吐司不能再追加第二份。新增供应仍须采购、等待、收货及拆取原料；原成功档继续时不自动补新菜单物资。见[沙拉批次记录](../openspec/changes/archive/2026-10-15-kitchen-multi-input-assembly/execution-notes.md)。

经营成长入口：单机选档“新开经营成长餐厅”，或Host房间“开启经营成长餐厅”。首关完成后选“装修 解锁现榨菜单”，第二关可切橙、榨汁和分杯；定义解锁不会补发食材或再造设备。第三关只开放田园沙拉，旧物、货物、已开始作业保留，但受限菜品不能新采购、投料、启动或从完成批次新盛装；共用番茄仍可用于合法沙拉。历史0/1/2资源批次及旧档保留原菜单基线。见[许可记录](../openspec/changes/archive/2026-10-15-restaurant-unlock-permissions/execution-notes.md)。

有限扩建沿经营成长餐厅的结算装修选择“扩建单客桌”，确认继续时区域从7×18扩到9×18并添加一张单客桌（桌7,3，座6,3），不补食材/餐具或复制顾客。选择时不会提前开地，失败保留原关与实物；再次已获得不重复安装。原厨房坐标不变，新增区域可点击/寻路，前厅仍可纵向拖看。新成功载荷v9保存实际几何，旧v1–v8按原7×18读取；文件与普通入口运行范围见[扩建记录](../openspec/changes/archive/2026-10-15-restaurant-space-expansion/execution-notes.md)。

普通选档可点“新开大关 1 · 家常开张”或“新开大关 2 · 进阶小馆”；Host房间使用对应“开启大关”按钮，队友只读。两章各三关，首章汤→汤/吐司→加田园沙拉，次章两沙拉/橙汁→加汤→加吐司；本关菜谱按开放菜单显示，首单提示缺省跟随配置首单。Solo终关保存完成后回选档，合作确认后回原房间，重选从独立厨房开始。旧档仍读原Next/库存；文件v9、wire31，参数与10项相关运行见[章节记录](../openspec/changes/archive/2026-10-15-restaurant-chapter-content/execution-notes.md)。

首批热餐从Solo“新开热餐餐厅”或Host房间“开启热餐餐厅”进入。经典牛肉汉堡需要汉堡面包×1+熟牛肉饼×1；香肠鸡蛋早餐需要熟香肠×1+煎蛋×1+烤面包×1，同盘明确组装。煎台放真实生料后点“煎制”；面包仍用原烤箱，完成前不能提前拿熟料。汉堡面包/生肉饼/生香肠均有有限生料补货；旧档不补新设备物资。两道菜共享原盘、清桌和洗盘流程。文件v10/wire32，具体13项运行范围见[热餐记录](../openspec/changes/archive/2026-10-15-kitchen-hot-food-batch/execution-notes.md)。

首批甜品从Solo“新开甜品餐厅”或Host房间“开启甜品餐厅”进入。预拌粉、鸡蛋、瓶装牛奶各一份加入搅拌机上的原盆，点“搅拌”得到有限两份面糊；拿空模具点“装模”，放入原烤箱并点“烘烤”，熟后拿原模具向空甜品盘点“脱模”。模具留在手上可再装最后一份；未脱模不能交付。拿起甜品盘向真实原味小蛋糕订单交付，之后由玩家清桌、伙伴洗盘。文件v11/wire33，半批/未完烤模随成功档恢复，旧档不补新物资；见[甜品记录](../openspec/changes/archive/2026-10-15-kitchen-dessert-batch/execution-notes.md)。

三款咖啡从Solo“新开咖啡餐厅”或Host“开启咖啡餐厅”进入。采购豆子，在磨豆机显式研磨；把咖啡粉加入咖啡机的接液壶，显式萃取有限四份浓缩液。牛奶加入蒸汽机上的奶缸，明确选“热奶”产四份热奶，或“打泡”产两份奶泡；完成后可搬走原缸，用第二缸制另一种基底。手持热饮杯逐份取基底：浓缩为咖啡1份；拿铁为咖啡1+热奶2，明确混合；卡布为咖啡1+热奶1之后最后加奶泡1，再混合。完成杯放贴单台，绑定同菜品有效订单，拿起交付；一次性杯消耗，之后仍须玩家清桌。杯包一次三只，豆/杯/牛奶均有限；已贴单杯先解绑才能加料。文件v12/wire34，半杯、停手混合、有限基底及未完模式随成功档保持，旧关贴单不恢复；见[咖啡记录](../openspec/changes/archive/2026-10-15-kitchen-beverage-batch/execution-notes.md)。
