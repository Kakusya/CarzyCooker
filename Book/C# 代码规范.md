# C# 代码规范

适用于新增及本轮修改的代码，不声称所有存量已符合。尽量保留参考通用规则，ET/生成字段按现有模式；不机械改名或格式化全仓。完整分层、owner、错误与异步约定见 [实现约定](../references/business-code-conventions.md)。

## 命名规范

### 代码命名

- 命名空间、类、方法（包括本地方法）、枚举、属性、常量、public 字段、public static 字段：`PascalCase`。
- 局部变量、方法参数：`camelCase`。
- GF private/protected/internal 实例字段：`m_PascalCase`；静态字段：`s_PascalCase`。ET 数据组件及生成字段遵循周围源码，不强改为 GF 风格。
- 缩写词通常只对首字母大写：`MyRpc`；已有框架 API/类型不机械重命名。
- 接口名字以 `I` 开头。

### 文件命名

- 文件名和目录名使用 `PascalCase`，中间不要加空格，比如 `MyFile.cs`。
- 文件名应该和里面的主要类型同名；生成路径由生成器决定。

## 代码组织

- using 以字母序排序，System.* 在前；修改时对齐周围文件，不全仓重排。
- 普通 GF 类成员按常量/静态字段、其他字段、构造/析构、事件/属性、方法、嵌套类型组织，分组内部按可见性组织；尽量将接口实现方法放在一起。
- ET Model/ModelView 持数据，Hotfix/HotfixView 的 System 持逻辑。按现有 EntitySystemOf/FriendOf/生成器约定组织，而不是改为另一套类架构。

## 编码规范

- 缩进 4 个空格，行末不要多余空格。
- 显式指定可见性，即使是默认值。
- 只在右侧类型显式可见时使用 var，例如 `var stream = new FileStream(...)`。
- 只在上下文类型明确时用 new()，对齐项目 C# 版本和周围风格。
- 禁止单行 if；分支写在下一行，推荐大括号。
- 生成物只读，改源/生成器；异步统一 UniTask，取消与资源释放由真实 owner 负责。

## 提交前检查 SOP

1. 核对仅有当前任务修改，保留用户未提交内容；检查生成物来源和当前程序集。
2. 改行为同步主规格、change 和对应说明；不将未来设计写成已实现。
3. 按风险验证真实成功、拒绝、取消等边界；C# 改动通过本工程编译，读取 Console 真实结果。
4. 执行 `git diff --check`，查看 diff 与引用；不运行全仓自动格式化，不新增检查器替代人工范围核对。
5. 分别报告编译、测试、联网、AOT 和产品构建；未运行写 NotRun。提交或推送按当轮明确授权。
