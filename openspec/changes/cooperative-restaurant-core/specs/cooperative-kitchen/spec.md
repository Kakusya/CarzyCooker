# Spec Delta

## Purpose

定义本机合作餐厅中本地 Host 与远端玩家共同制作两道代表菜的基础合同，明确共享控制、业务时间、加入就绪和成员退出。仅覆盖内存餐厅与本机真实传输，不把可制作菜品扩大为完整前厅、持久经营或跨设备交付。

## ADDED Requirements

### Requirement: 正式合作餐厅唯一驱动

正式 Host SHALL 启动与 Solo 同一语义的持续厨房及当前关，远端仅观察其独立投影。加工、角色、顾客与已有组件只由一个业务时钟推进；网络心跳、通知或渲染不得产生第二次推进。Solo 保持无监听入口。

#### Scenario: 两端加入同一家餐厅
- **WHEN** Host 启动并与远端完成加入
- **THEN** 两端观察同一世界和当前关，只有一份厨房，推进一个业务步只增加一次业务时间

#### Scenario: 暂停仍能恢复
- **WHEN** Host 暂停后等待并请求恢复
- **THEN** 已开始加工与当前步进度冻结，未执行动作取消，恢复请求仍可答复，恢复后不重放已取消目标

### Requirement: 可信 Host 共享控制

开店、暂停／恢复、继续、布局与共有 Buff MUST 只接受当前 Host 本地玩家的可信在线绑定。成员编号、角色字段、工作区或机器身份均不能授予控制权。队友仍能合法制作；Host 本地离开不转移共享控制。

#### Scenario: 队友伪装 Host
- **WHEN** 远端自报 Host 身份请求开店、换关、布局或 Buff 选择
- **THEN** 明确拒绝且阶段、选择、布局和实物均不变；同一成员之后的合法个人制作仍可执行

#### Scenario: Host 选择与队友查看
- **WHEN** Host 合法调整准备态布局并选择本关 Buff
- **THEN** 两端观察相同布局与选择，队友不会获得可执行的共享控制权限

### Requirement: 两菜制作经同一裁决

本地与远端 SHALL 能交接原料并完成汤的投料、启动、搬锅、有限盛装，以及吐司烘烤和装盘。材料、容器、作业、到位与阶段校验相同；入口接受不等于加工完成，失败保留原实物，重放不重复产出或扣份。

#### Scenario: 分工完成汤与吐司
- **WHEN** Host 备料后由 Client 接手后续加工和盛装／装盘
- **THEN** 两端观察同一原料转移、真实进度和成品容器，未到加工时间不能提前取得成品

#### Scenario: 争抢最后一份
- **WHEN** 两个合法成员请求同锅最后一份汤
- **THEN** 只有首个合法提交产生一份成品，另一只碗保持原状态，剩余份数不为负

### Requirement: 加入与餐厅可操作分离

客户端 MUST 在确认本人成员、匹配的世界／当前关／绑定以及本人角色和必要视图后才开放输入。各端复制同版数据，消息回收后仍有效；旧世界、旧关、失效绑定或旧结果不得覆盖新状态。

#### Scenario: 快照先于加入答复
- **WHEN** 餐厅快照先到而本人加入尚未确认
- **THEN** 客户端不开玩法输入；后续身份确认匹配后才安装有效数据并进入可操作状态

#### Scenario: 旧关高版本到达
- **WHEN** 新关已安装后收到更高数值版本的旧关快照
- **THEN** 仍按关身份拒绝，当前物品、角色与可操作状态不回退

### Requirement: 成员退出保留持续厨房

单成员断线或已提交 Leave MUST 失效其未执行动作，移除角色并把同一手持物留在最后提交格；进行中的自动批次继续、手工工作可被队友接续。断线保留离线成员，Leave 移除成员，共享消息资源持续可用。整轮结束停止本轮业务，不伪造结算或新轮成果。

#### Scenario: 持锅成员失联
- **WHEN** 成员持有正在加工的锅失联，随后重复触发清理
- **THEN** 只落下同一锅一次，同批次继续推进，队友可依法拾取，旧成员动作不能控制它

#### Scenario: 退出后新开
- **WHEN** Host 技术关闭并创建新运行
- **THEN** 旧等待、视图回调及消息只收尾，不向新厨房补入旧物品或成功结果
