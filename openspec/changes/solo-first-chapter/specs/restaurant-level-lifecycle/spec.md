# Spec Delta

## MODIFIED Requirements

### Requirement: 单机试玩与持久检查点区分

系统 MUST 区分未选档的新开试玩与已成功发布的检查点。技术关闭释放当前餐厅，不将临时进度宣称为已保存；正式 Solo 继续须遵守成功检查点及保存失败阻止换关合同。首个三关大关的终关保存完成记录而不生成下一关，禁止用空保存冒充持久提交。

#### Scenario: 结束程序后重新开始
- **WHEN** 玩家关闭本轮运行并重新进入，选择新开而非继续有效检查点
- **THEN** 创建新的餐厅与初始物资，不显示刚才未发布的临时进度已经写盘；已有有效记录仍可单独选择

### Requirement: 固定订单得分与零星成功

成功订单 MUST 按配置基础分只计一次，未满足订单计零且不倒扣。总分按递增关卡阈值显示零至三星，零星仍正常完成；非终关允许继续，明确终关按大关完成流程保存并返回选档。技术中断不能生成成功结算，不添加正常业务失败界面。

#### Scenario: 没有完成任何订单
- **WHEN** 顾客和前厅按规则排空，成功订单数为零
- **THEN** 显示零分及适用星级，不要求重试或强制补单；非终关允许继续，终关仍允许保存完成并返回选档

### Requirement: 内存换关保留实物而重置临时状态

非终关继续 MUST 在完成态仅安装一次新 Level；保留厨房物品、容器内容、剩余份数、工位布局和加工进度，禁止再次叠加初始物资。旧角色结束前先保留手持物于最后提交格；新角色使用新关出生位。顾客订单、计时得分、认领、成长、buff 和旧关权限重置，新关只读取新配置。明确终关不得通过继续创建新 Level，须采用完成记录流程。

#### Scenario: 重复继续与旧关动作
- **WHEN** 非终关完成态继续请求被重放，之后旧关动作迟到
- **THEN** 只安装一个新关，物资和批次不补满，旧关动作不能修改新关

#### Scenario: 终关旧继续请求
- **WHEN** 终关完成后收到继续或旧 UI 回调
- **THEN** 不创建下一关、不发装修、不重建初始物资，保留终关结果供完成记录流程处理
