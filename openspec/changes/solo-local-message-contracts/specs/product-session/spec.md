# Spec Delta

## ADDED Requirements

### Requirement: 产品命令上下文与类型明确

新增单机产品命令 MUST 携带所属运行世界、适用关卡、绑定代次和正业务编号，并用明确动作及目标身份表达意图。入口根据真实绑定确定发送者，不接受请求自报内部地址或成员身份。关卡建立前的既有格子命令保持原上下文；关卡建立后，新关命令不得省略关卡身份。

#### Scenario: 旧关与伪造身份请求
- **WHEN** 请求属于上一关、失效绑定，或试图使用另一发送者的内部身份
- **THEN** 明确拒绝，不修改当前物品、布局、订单或关卡状态

### Requirement: 最新命令重放与有限结果保留

同一绑定各新增动作族 MUST 共享单调递增的业务编号。最新已接收编号与相同完整载荷重放时返回当前接收／最终事实，不再次执行；同编号不同动作或目标须拒绝，更早编号返回已过期，不保存无限历史或自动重试。业务编号不得用 RPC 编号替代。

#### Scenario: 最新请求重复与编号冲突
- **WHEN** 最新请求重复到达，随后同编号被用于另一目标
- **THEN** 重复返回原接收或最终结果，冲突明确拒绝，世界效果仍只有一次

#### Scenario: 历史结果已不保留
- **WHEN** 较新请求已接收，调用者重放更早编号
- **THEN** 返回已过期且不执行，不把缺少历史结果解释成可以再做一次

### Requirement: 接收动作和工作完成分离

入口 MUST 快速返回接受或拒绝，最终业务结果在共同 Tick 验证提交后产生。接受、到达、成功启动、加工完成及取消属于不同可观察事实；公共入口不得等待整段行走、加工或营业时间。

#### Scenario: 加工请求已经接受
- **WHEN** 请求得到接收回执但角色尚未到位或加工尚未到点
- **THEN** 显示对应进行中事实，不提前报告物品已转移或加工已完成，其他请求仍可处理

### Requirement: 取消业务等待保留原调用收尾

调用者退出 MUST 及时结束其业务等待，同时让原物理本地调用由答复、既有有限超时或整体停止收尾。产品入口在途保护须持续到该原调用结束；取消不能提前释放仍承接原消息的入口、重复回收消息或停止公共发送器。原调用结束后的迟到结果不得写入新调用者。

#### Scenario: 界面退出而答复尚未到达
- **WHEN** 界面关闭取消对外等待，原本地请求仍在队列或等待答复
- **THEN** 界面等待为取消，原入口按在途责任保留到收尾，另一调用者仍可正常通信，晚到响应只被收尾

### Requirement: 单机真实消息测试入口

单机功能测试 MUST 能创建隔离产品运行与本地客户端，经真实请求、队列、接收 handler 和业务 Tick 观察结果。测试须分别控制消息投递和业务时间，清理自身运行，拒绝占用正在运行的产品；不能以直接调用 handler 或修改最终状态冒充消息与完整输入验收。

#### Scenario: 控制收到请求与执行时点
- **WHEN** 测试泵入真实本地请求但尚未推进业务 Tick
- **THEN** 可观察接收回执而世界尚未提交，推进 Tick 后才取得动作结果，测试结束无所属运行残留
