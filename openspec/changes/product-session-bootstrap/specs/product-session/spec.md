# Spec Delta

## Purpose

为产品提供可在本机验证的最小 Host／Client 会话，明确本地与远端玩家的共用裁决、成员状态、消息与运行生命周期。该能力只建立会话基础，不宣称厨房玩法、持久进度、正式传输选型或重连恢复已经成立。

本规格依据交接 A3／G3 捕获最小 Match／Participant 与连接分离，断线保留离线成员。自动重连、成员恢复凭证、Profile 和厨房尚未纳入本原型，不以新连接成立冒充旧身份恢复。

## ADDED Requirements

### Requirement: 产品会话所有者与角色分离

产品会话 MUST 通过 ET Child／Component 关系持有本轮状态、入口及下级资源。Host 同时包含权威会话和本地客户端，远端 Client 仅包含客户端；运行角色不得由主线／稳定工作区职责决定。成员权威和客户端投影须分开，不共享可变业务状态。

#### Scenario: 启动 Host
- **WHEN** 合法 Host 配置进入产品入口
- **THEN** 创建本轮权威会话及本地客户端，本地玩家必须获得真实加入确认，不能仅因拥有 Host 而报告已加入

#### Scenario: 启动远端 Client
- **WHEN** 合法 Client 配置进入产品入口
- **THEN** 仅创建本端客户端，通过指定目标加入，不创建本端成员权威或使用 Demo 账号服务

### Requirement: 逻辑成员独立于连接

Match MUST 独立持有 Participant 和名单权威，HostPeer／Session 只绑定成员，不作为其释放父对象。连接断开仅撤销绑定并标离线，显式 Leave 才退出逻辑协作；原型不提供身份恢复凭证，不准凭自报编号接管旧成员。

#### Scenario: 断线释放连接子树
- **WHEN** 某已加入 Session 及其 HostPeer 被清理
- **THEN** 原 Participant 由 Match 保留，在线状态变为离线，其他成员及公共消息资源不受影响

#### Scenario: 新连接自报旧成员编号
- **WHEN** 新绑定试图用请求自报的旧 MemberId 恢复身份
- **THEN** 不授予原成员权限；本原型仅允许合法新加入，旧成员继续离线，不宣称完整重连已实现

### Requirement: 本地与远端共用裁决

Host 本地玩家 MUST 使用进程内消息发送与接收，不向自己发送 UDP。远端入口只处理传输、可信身份绑定和转交；两种路径的加入、主动退出及最小命令须进入同一套权威处理，不因本地身份绕过验证。成员状态的修改须统一有序提交。

#### Scenario: 两种路径执行同一请求
- **WHEN** 已加入的本地玩家与远端玩家提交同一种无玩法探测请求
- **THEN** 进入相同权威处理，分别得到自己的成员编号及请求数据，答复不会互相匹配

#### Scenario: 请求自报他方身份
- **WHEN** 请求试图指定另一个成员或内部 Actor 地址
- **THEN** 入口使用实际绑定身份裁决，伪造内容不能替换成员或直达内部处理

### Requirement: 加入确认与协议兼容

系统 MUST 区分连接建立与加入成功；只有取得当前 Match 的成功答复、本人成员编号和有效名单后，客户端才进入已加入。加入须核对明确协议版本，提交前失败不留成员，提交后答复丢失保留 Match 所属离线成员；不得自动重试、更新稳定基线或回落 Demo。

#### Scenario: 连接建立但尚无答复
- **WHEN** 连接已经建立，加入确认尚未到达
- **THEN** 客户端保持加入中，不发布加入成功，不允许发送已加入成员命令

#### Scenario: 协议不兼容或加入失败
- **WHEN** 本端与 Host 协议版本不兼容，或当前请求加入失败
- **THEN** 返回明确失败并收尾本请求资源，不报告成功、不自动更新另一端

#### Scenario: 同一绑定重复加入
- **WHEN** 已加入绑定再次请求加入
- **THEN** 不新增第二个成员，返回既有加入结果或明确重复错误

#### Scenario: 等待加入期间退出
- **WHEN** 客户端在加入确认前退出
- **THEN** 旧答复不能把客户端改为已加入；未提交登记不创建成员，已经提交的成员离线且由 Match 持有，不因取消等待删除逻辑身份

#### Scenario: 加入已提交但答复未送达
- **WHEN** Host 已提交成员登记，随后连接断开导致确认无法送达
- **THEN** Host 保留同一成员并标离线，Client 不宣告 Joined，不自动重试或删除该逻辑身份

### Requirement: 名单快照与本轮隔离

Host MUST 唯一维护 Match 的逻辑成员名单及在线／离线状态，每次实际变更生成递增版本完整快照。客户端只应用所属 Match 且不旧于当前版本的数据；来自其他 Match 或失效实例的数据不得应用。投影独立，HostSession 不建立第二份可写名单。

#### Scenario: 两端加入后的名单
- **WHEN** 本地玩家与远端玩家完成加入并收到当前名单
- **THEN** 各端对同一版本观察到相同成员，客户端数据不引用 Host 可变成员实体或容器

#### Scenario: 旧快照迟到
- **WHEN** 较旧名单快照或上一轮会话数据迟到
- **THEN** 不回退当前名单版本，不写入另一轮客户端状态

#### Scenario: 通知早于加入答复
- **WHEN** 名单通知在本人加入确认前到达
- **THEN** 可以暂存当前会话数据，但不提前宣告加入；后续加入答复中的旧版本也不能覆盖较新名单

#### Scenario: 尚未确认 Match 的通知
- **WHEN** 正在 Joining 的 Client 收到完整名单，尚未确认其 MatchId
- **THEN** 仅在当前入口下保留候选数据，待本人 Join 确认匹配 MatchId 后才安装，其他 Match 的通知不能设定当前身份

#### Scenario: 相同业务编号的旧绑定回复
- **WHEN** 旧入口回复或通知在本端下一轮接入后到达
- **THEN** 先核对本轮实例和绑定身份，不能仅因 MatchId 或 MemberId 相似就应用到新绑定

### Requirement: 协议入口白名单与参数校验

产品入口 MUST 核对协议版本、合法消息类型、当前 Match、必需字段与明确载荷限制，拒绝未知或内部消息。身份来自可信接入绑定，不来自请求自报成员、Actor 地址或机器身份。心跳只维护连接，不增加成员或成为世界时钟。

#### Scenario: wire 发送内部转交消息
- **WHEN** 远端构造仅供进程内共同裁决的消息类型
- **THEN** 入口拒绝转交，不授予内部身份，也不修改 Match

#### Scenario: 无效探测载荷
- **WHEN** Probe 使用错误 Match、缺失必需字段或超出明确载荷限制
- **THEN** 返回明确拒绝，不回落 Demo，不创建成员或修改名单

### Requirement: 消息与结果所有权

请求、答复和通知 MUST 具有明确释放者，转交须保留各段独立答复关联，不能由内部调用改写原网络请求编号。多人通知不得共享会被接收者回收的同一消息对象，客户端须在回收消息前取得独立状态数据。成功、业务失败、超时和退出须明确区分。

#### Scenario: 网络请求转交本地处理
- **WHEN** 远端请求经过进程内 RPC 后返回
- **THEN** 远端收到匹配原网络请求的答复，内部编号只用于内部等待，不建立另一份私有回调表

#### Scenario: 消息回收后读取投影
- **WHEN** 已处理的消息对象被回收或复用
- **THEN** 客户端成员名单和已接收结果保持有效，其他接收者不读取被回收消息

### Requirement: 状态事件与启动结果

业务 MUST 先提交所属状态再发布观察事件；事件不替代跨进程消息、请求答复或必须成功的初始化步骤。根启动、监听可用和成员加入各有明确结果，记录处理器异常或发布完成本身不能证明产品就绪。

#### Scenario: 初始化失败
- **WHEN** 必需初始化步骤失败，但某个事件发布已经返回
- **THEN** 保留真实失败，不进入已加入或报告 Host 完全就绪

#### Scenario: 成员状态通知
- **WHEN** 发布加入或名单变化事件
- **THEN** 观察者读取已经提交的所属客户端或 Host 状态，不能通过事件形成第二份权威

#### Scenario: 事件观察者处理名单变化
- **WHEN** 已提交名单触发本端观察事件
- **THEN** 观察者只读取当前版本，不再次提交同一变更，不增加名单版本，也不触发另一产品角色的初始化

### Requirement: 监听与连接存活

原型 SHALL 仅连接本机 loopback。Host 监听必须报告实际绑定的非零 endpoint，端口冲突明确失败；不将配置端口 0 或 Pipeline 工具端口交给 Client。远端加入成功后须解除接入验证超时并维持有界心跳及既有空闲断线检查，本地消息通道无需网络心跳。

#### Scenario: 动态监听端口
- **WHEN** Host 配置以端口 0 启动
- **THEN** 报告实际绑定地址和非零端口，另一端显式使用该结果；不猜测或扫描替代端口

#### Scenario: 连接保持空闲
- **WHEN** 已加入的远端连接没有业务命令但双方正常运行
- **THEN** 心跳使连接正常保持；对端失联时有限时间内结束等待并报告失联，不无限积累请求

### Requirement: 单成员与整体退出边界

已提交显式 Leave SHALL 移除当前 Participant 及绑定，重复退出不重复变更名单。意外断线 MUST 立即使入口失效、结束该 Session 网络等待并将成员离线；本地在途请求经拒绝或既有有限超时结束，不承诺单请求即时取消。Leave 未提交的本端关闭按断线处理。整体退出解散 Match，先拒绝新工作再结束本轮等待与资源；单连接退出不停止共用发送器。

#### Scenario: 单个成员主动退出
- **WHEN** 已加入 Client 的显式 Leave 已提交并随后重复清理
- **THEN** 该成员只被移除一次，其他成员继续通信，共用发送器仍可用

#### Scenario: 远端连接意外断开
- **WHEN** 已绑定的远端 Session 退出
- **THEN** 旧绑定失去命令资格，网络等待结束、本地在途请求按约定收尾，逻辑成员离线保留；重复清理不增加名单版本，不自动重连

#### Scenario: 关闭时仍有已排队请求
- **WHEN** 一个连接关闭，仍有其已接入的本地请求等待共同裁决
- **THEN** 请求在提交前重新核对入口并明确拒绝，处理入口保留到在途收尾；其他玩家继续通信，不停止公共发送器来取消单成员请求

#### Scenario: 动作提交后发生断线
- **WHEN** 合法 Join 或 Leave 已经提交，随后原连接失效
- **THEN** 保留已提交事实，不将丢失答复当成未执行，不向新连接交付旧答复

#### Scenario: Host 本地玩家单独退出
- **WHEN** Host 本地 Client 的 Leave 已提交，而 Host 根未停止
- **THEN** 只结束该本地成员和接入，Host 监听及其他成员继续工作，不自动重新加入本地玩家

#### Scenario: Leave 尚未提交时关闭
- **WHEN** Client 发出 Leave 后立即关闭，Host 尚未合法提交该请求
- **THEN** 不宣称成员已经离开，旧入口命令被拒绝并将成员离线保留

#### Scenario: Host 整体退出
- **WHEN** Host 本轮运行结束或启动中失败
- **THEN** 拒绝新加入和命令，结清本轮本地／网络等待并清理已创建资源，旧异步结果不写入下一轮，不释放其他工程资源
