# 实施前测试条件

这些是已确定的验收输入，不是已有测试或通过证据。先按这些条件建立可执行小集，再改公共实现；新增 API 的最小声明可与测试一起加入，不把编译错误当作已复现的行为失败。

## 测试设施与观察量

复用现有 UTF 和 Tools/AutoTesting，不引入新测试框架、独立 runner、探针或证据包。小集控制底层何时成功/失败、是否永不回调，记录业务写回次数、请求终态、当前 owner 在途数量和资源引用释放次数；测试替身只替代底层时序，不替代待测 scope、取消或回收逻辑。

owner 取三种必要代表：普通可关闭/再打开的生命周期、真实公共 Mono 入口、ET EntityRef/InstanceId 的释放复用。先用普通 owner 覆盖公共规则，再用真实入口证明适配，不为每个基类重复全矩阵。原生资源另外验证，模拟不证明原生卸载。

## 关键条件与预期

| 编号 | 条件与动作 | 必须观察到的结果 |
| --- | --- | --- |
| T1 | 有效 owner 执行资源加载、延时和代表请求；分别成功和失败 | 正确结果和真实失败；结束后所属业务登记为零；正常资源只按所属生命周期释放 |
| T2 | 底层永不完成且不发任何回调，此时关闭 owner | Stop 返回前未完成业务等待已为取消；不推进 PlayerLoop/Timer；不要求调用者 finally/卸载代码；已结束结果不改写 |
| T3 | 关闭后分别送成功、失败、进度和依赖通知 | 写回次数为零；迟到成功按该请求释放一次；类型不匹配的旧结果也不能转成旧 owner 的新异常；其他通知不污染新轮次 |
| T4 | 关闭/回收，再打开或复用为新实例，新请求启动后旧结果到达 | 新请求继续正常；旧实体同业务 Id/不同 InstanceId 不被使用；旧任务和等待记录不提前复用 |
| T5 | 调用者不 await、不 GetResult，或使用由公共入口观察的 fire-and-forget | 在正常终结及取消时业务登记、注册和引用照常清理；清理不依赖结果消费；真实失败被统一观察，预期取消不报成成功或意外 Error |
| T6 | 顺序完成→关闭、关闭→完成、完成通知内重入关闭；再重复关闭 | 每个结果终结一次；先完成事实保留；先取消不会变成功；清理只作用于捕获旧批次，不能删除重入后新记录 |
| T7 | 两个 owner 共享资源系统或 Session，只关闭其中一个 | 只取消所属等待/引用；另一个正常完成；共享 sender/Session 不被单 owner 停止，原资源引用计数不被重复扣除 |
| T8 | 全运行退出；底层不再回调，退出后也不再推进 owned 更新循环 | 退出调用内业务等待取消、拒绝新工作、原 owner 写回失效；拆卸后不访问 GameEntry 当前 manager；重复退出不影响下一运行 |
| T9 | 任务忽略/捕获取消后仍尝试通过上下文写回；同时核对无 owner 的普通业务启动 | 受控写回被拒绝；受管入口不默默退成永久有效 scope。任意直接字段写入不是此断言的保护范围 |

T2/T3 至少覆盖 callback 与 await 两种资源消费；T2 还覆盖延时和可取消的请求等待。T7 请求验证只需要一条现有 Session.Call 路径，不新增聊天或玩法，不重跑全部双 Editor 联调。本地 RPC 单请求适配如使用已有 sender：只保证业务等待取消，原物理等待沿既有有限超时/答复回收；全运行 Stop 复用原 sender.Stop，不能宣称单 owner 已清空 sender 的所有等待。

## 一条真实 Unity 资源验证

采用当前 Unity 6000.3 的资源入口，复用现有适用资源；必要的微型 AssetBundle 只放 Unity/Temp 的测试临时目录，构建测试资源不等于产品 Player 构建。先确定操作确实进行中，再关闭原 owner/停止其运行；检查无迟到业务写回、资源引用按所属者释放、下一轮仍能加载和正确回收。一次路径可同时观察正常完成和关闭后处理，不追加没有疑点的重复运行。

EditorResourceMode 的资源路径和 AssetBundle 原生请求证明范围不同。真实进行中 AssetBundle 无法触发或验证时明确 NotRun，不能拿 Editor 直读/模拟通过冒充。若原生卸载、依赖关系或停止后的事件产生异常，修复对应资源适配并新建该小集运行，保留原失败输出。

业务登记清零不等于原生句柄已释放。Unity 引擎仍运行时，退役原生操作可在引擎完成时收尾，记录它尚在进行，不能使用已销毁 manager；如果完整进程已结束，不承诺执行后续完成代码。强杀/断电不进入正常退出通过判定。

## 运行与报告边界

实际执行须先发现本工程 ready 的 Editor、模式和新增测试 filter，按当前 apply 授权使用既有 SOP；本次创建提案不启动 Editor 或测试。过滤当前新小集及必要代表路径，复用既有 sender/会话证据。不清 Console，不自动取消其他作业。

每项区分 Passed、Failed、Skipped、NotRun；空集与未完成作业不能算通过。记录原输出位置、失败原因和真实终态，修复后开新运行。没有明确疑点不扩展性能测量、Player/AOT、物理 LAN 或全仓回归。
