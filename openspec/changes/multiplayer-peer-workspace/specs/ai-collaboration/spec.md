# Spec Delta

## ADDED Requirements

### Requirement: 主线与稳定对端协作职责

主线与稳定对端的 AGENTS MUST 保留共同项目纪律，以简短职责片段引用一份共用协作规程，并说明真实分支身份。主线负责需求、实现和基线维护决策；稳定端默认只运行、观察与回报，修改源码或更新基线须有明确授权。工作区职责不得决定运行时 Host／Client 角色。

#### Scenario: 稳定端收到运行请求

- **WHEN** 主线在已有授权范围内请求稳定端运行或诊断
- **THEN** 稳定端执行获准操作并回报实际结果，不自动修代码、拉取主线、创建提案或推进归档

#### Scenario: 共同纪律与角色差异

- **WHEN** 维护两端 AGENTS
- **THEN** 保留相同的技能、授权、生成物、现场保护和 ET 树／本地消息设计约定，只维护必要职责差异，共用规程保留唯一正文

### Requirement: 活跃终端请求与完成回报

跨工作区协作 MUST 复用现有活跃终端通信，请求携带 runId、目标 Unity 工程完整路径、运行角色、适用 endpoint、操作和观察范围。发送入队、收件确认、执行开始与最终结果 MUST 分开报告；无法证明收件时不得声称对端已执行，也不得假定终端关闭后消息仍持久有效。

#### Scenario: 发送成功但对端尚未读取

- **WHEN** 消息成功入队而没有对端确认
- **THEN** 主线只报告已发送，通过当前终端输入或人工提示触发收件检查，不能把发送成功解释为启动或测试完成

#### Scenario: 对端确认并回报

- **WHEN** 对端实际读取请求并接受操作
- **THEN** 确认实际 projectPath 与 runId，在原线程回报开始和最终结果，附实际失败原因及原日志位置，不新增证据快照

### Requirement: 协作请求拒绝与现场保护

接收端 MUST 核对目标、授权、当前状态和请求是否已处理；重复、已作废、目标错误或忙碌请求须说明拒绝原因，不重复启动、不取消已有操作。超时和会话重建须先重新发现终端并核对在途运行，不自动重发执行请求或伪造后台 worker 生命周期。

#### Scenario: 重复或作废的请求到达

- **WHEN** 同一请求已执行，或该 runId 已明确取消／结束
- **THEN** 回报已有结果或拒绝原因，不再次进入 Play；判断仅限当前活跃协作上下文，不宣称跨重启全局去重

#### Scenario: 终端重建或回报超时

- **WHEN** 旧终端失效或尚未收到最终回报
- **THEN** 重新发现目标终端并核对 Editor 状态，未弄清在途操作前不自动重发、停止运行或改用另一工程
