# Spec Delta

## Purpose

为同设备单机餐厅提供成功后的主动检查点保存与重启继续，让玩家恢复持续厨房及下一关准备状态。文件记录、长期归属与本轮运行身份分开，失败保持最近成功档，未知或损坏载荷明确拒绝，不把运行快照和技术中断当作成功记录。

## ADDED Requirements

### Requirement: 本机身份和轻量选档分离

系统 SHALL 使用本机稳定玩家身份及独立存档身份、版本、修订和平台标签。浏览只读轻量元数据，只有被选择且完整校验通过的档才创建运行餐厅；未绑定存档的内存试玩保持原合同。首版仅本设备 PC 单机，不提供他人授权或跨平台导入。

#### Scenario: 浏览与非法选择

- **WHEN** 玩家浏览多份记录并选择损坏、未知版本或平台不匹配的记录
- **THEN** 浏览不创建多个世界，非法选择明确拒绝且不静默新开餐厅，不改写原记录

### Requirement: 成功结果与运行中快照分开

产品检查点 MUST 只来源于自然 Completed、前厅收口及结算选择确定后的不可变结果。准备、营业、半条命令或技术中断不得生成成功结果或覆盖最近记录；零星仍是合法成功。结果绑定本机玩家及当前成功身份，不在退出释放时临时补结算。

#### Scenario: 零星与营业中退出

- **WHEN** 玩家分别零星自然完成或在营业中直接退出
- **THEN** 前者可以主动保存，后者保留最近成功记录且不生成本关检查点

### Requirement: 主动新建提交后才换关

玩家 MUST 显式选择保存成功结果并继续；首版只新建独立记录，来源档不覆盖、不合并。写入成功后才能安装/公布下一关。写入失败、容量不足或目标冲突时保持原档、成功结果和结算态，允许原结果重试，不报告已经保存。

#### Scenario: 保存失败后重试

- **WHEN** 新建检查点在持久提交前失败，随后玩家重试
- **THEN** 失败期间未安装下一关且旧档完整；成功后只公布一个新记录并进入对应准备态

### Requirement: 同结果本机领取最多一次

本机保存 MUST 以成功结果和玩家身份保证一次新建。重复点击、保存后继续响应丢失或重新查询均返回同一已提交结果，不生成额外记录；发送回执不能代替持久提交。此保证不扩展到跨设备凭证。

#### Scenario: 提交成功后界面重开

- **WHEN** 保存已提交但界面尚未收到结果，随后重开并再次请求
- **THEN** 返回原记录身份，不创建第二份记录，也不再次安装下一关

### Requirement: 持久载荷完整表达持续状态

检查点 MUST 包含物品位置与容器关系、脏净状态、批次剩余份数、加工已提交进度和冻结参数、工位布局及装修、有限供应余额和在途/待收货。待执行命令、连接、当前角色认领、旧投影水位及引擎对象不得进入产品载荷。

#### Scenario: 保存剩菜及在途货

- **WHEN** 成功时厨房保留半锅汤、暂停加工及运输中的采购
- **THEN** 记录保持真实剩余份数、加工进度和剩余运输时间，不把已消耗材料或货物配额补满

### Requirement: 校验完整载荷后恢复新运行

载入 MUST 完整验证定义、引用、唯一位置、容量、加工和下一关配置后才安装世界，使用新的运行与关代次及新角色。只从载荷重建持续实物，不同时再发初始物资；必要字段缺失或非法引用拒绝，不用空集合伪装有效旧档。

#### Scenario: 实际重启继续

- **WHEN** 程序结束后重新启动并选择此前成功记录
- **THEN** 使用新运行身份进入下一准备态，原实物关系、进度和份数恢复，旧命令无效且初始库存不叠加
