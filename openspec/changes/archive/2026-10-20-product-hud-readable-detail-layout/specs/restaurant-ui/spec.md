# Spec Delta

## ADDED Requirements

### Requirement: 入口与经营界面使用稳定的空间分区

界面 SHALL 在入口提供标题、正文或列表、固定导航，在正常经营态提供阶段摘要、完整厨房地图视口、手持/目标摘要和动作区域。长说明按需展开，不以常驻长文挤占厨房；查看前厅保留纵向拖动。入口、选档、结算和现有合法功能均可从当前页面到达。

#### Scenario: 从选档进入厨房

- **WHEN** 玩家在540×960视口从入口打开选档、开局预览并进入准备
- **THEN** 各页文字和主要按钮不相互遮挡，正常经营态厨房完整可见，查看前厅的拖动不附带业务动作

### Requirement: 代表视口与字号下保留真实可操作区域

界面 MUST 在540×960、1920×1080及一个非零安全区代表环境中保持主要控制和固定返回可触达；最大已有字号不能使文字或操作永久消失。详情覆盖区消费指针，装饰不阻挡有效按钮；关闭后恢复当前选择和地图查看位置。

#### Scenario: 最大字号下关闭详情并操作

- **WHEN** 玩家在非零安全区和最大字号下滚动长详情，使用真实指针点击固定返回，再点击地图当前有效目标
- **THEN** 返回收到输入且不穿透，地图选择和镜头恢复，随后一次合法动作只提交一次请求

#### Scenario: 宽屏入口和结算

- **WHEN** 玩家在1920×1080进入入口和真实结算
- **THEN** 主内容与固定导航均可阅读和触达，控制仍遵守原阶段与权限

### Requirement: 密集详情与动作列表的可读布局可从原入口访问

系统 SHALL 独立调整现有 HUD 的详情与长列表布局：明确可滚动正文和固定关闭/返回区，动作列表与正文滚动分离，长中文可完整阅读；详情关闭后恢复地图操作区，保留相关结果列表的有效滚动位置。

#### Scenario: 密集详情与动作列表的可读布局的实际使用

- **WHEN** 540×960 打开最长已交付菜谱或实际长工作/查找列表，滚动到末尾后返回地图
- **THEN** 正文末尾与返回控件都可触达，滚动不触发地图命令，关闭后真实点击原目标仅发送一次

### Requirement: 密集详情与动作列表的可读布局遵守实际业务边界

系统 MUST 使说明与当前已提交状态一致。仅处理现有 UIGridKitchen 结构/绑定和对应消费者，不改业务权限、表配置语义或创建第二套菜单框架；不承诺已完成 Android 真机适配，也不先造 UI 结构 runner。

#### Scenario: 密集详情与动作列表的可读布局在目标变化后失效

- **WHEN** 非零安全区、HUD关闭重开或打开中退出，旧按钮随后触发
- **THEN** 布局不遮盖必要控制，旧回调无效，无重叠订阅或残留视图；重开后的真实操作仍可用

### Requirement: 密集详情与动作列表的可读布局可安全关闭重开

系统 MUST 在关闭、重开和运行/绑定变化后清理旧显示上下文；阅读不分配业务命令、认领工作、推进时间或改变权限。原合法动作仍可从有效页面明确执行；同一次点击至多提交一次原请求，暂停不因打开详情而恢复。

#### Scenario: 旧页面回调不能影响新运行

- **WHEN** 页面关闭重开或当前运行已改变，旧回调随后到达，玩家再点击一次原合法动作
- **THEN** 旧回调失效，新动作只作用当前有效身份且至多提交一次；受限角色不能因进入本页取得控制权
