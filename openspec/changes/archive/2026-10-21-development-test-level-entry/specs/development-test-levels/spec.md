# Spec Delta

## Purpose

为项目开发者提供游戏内可选择、可重开的有限测试关卡入口，直接进入已交付章节小关或既有功能菜单。测试世界保持真实操作规则，并与正式存档、领取进度和正常游玩路径分离，缩短重复验证的准备过程。

## ADDED Requirements

### Requirement: 测试入口受开发环境和运行角色限制

系统 SHALL 仅在 Unity Editor 或 Development Build 的主菜单提供测试关卡。实际启动边界必须再次验证环境与单人角色；正式非开发环境拒绝测试启动，不能仅隐藏按钮。Host、Client 和 legacy 请求不得借测试入口绕过原角色、网络及房间规则。

#### Scenario: 开发环境打开测试目录
- **WHEN** 用户在允许的开发环境从普通首页选择测试关卡
- **THEN** 显示测试目录，不创建餐厅或监听，普通新开、继续和合作仍可访问

#### Scenario: 不允许环境或角色请求测试
- **WHEN** 非开发环境收到测试启动意图，或测试意图指定 Host、Client 或 legacy
- **THEN** 明确拒绝，不创建测试世界、不修改正式记录、不回落到另一测试或旧示例

### Requirement: 测试目录来自有限且有效的已交付内容

系统 SHALL 提供章节小关与功能场景分组，包含当前正式章节的 Solo 小关、基础操作及已有独立菜单首关。每条显示名称、菜单、起始准备阶段、测试目的和不保留正式进度的说明；仅允许选择有效目录条目，不接受任意原始关卡编号。记住当前应用内上次选择，不保存测试世界。

#### Scenario: 选择章节后直接测试第二小关
- **WHEN** 用户选择正式章节的第二小关并明确进入
- **THEN** 从该小关准备阶段新开测试，无须先完成第一小关，页面所示菜单与实际起点一致

#### Scenario: 目录条目失效
- **WHEN** 选择所需的关卡、菜单、工位或原料配置失效
- **THEN** 条目不可启动并说明原因，确认前后均校验，不静默改开另一关或补用正式记录

### Requirement: 测试起点具备可操作的临时前置

系统 MUST 在新建测试世界时按当前有效配置初始化目标关卡、对应厨房布局、有限原料和所需生产许可。指定中间小关不得依赖玩家真实前序进度；保留该关真实菜单、准备要求、顾客与关链。测试世界不宣称复刻正式旧档、历史装修或先前库存，不自动跳到营业、结算或完成状态。

#### Scenario: 中间小关完成真实操作
- **WHEN** 用户进入一个非首关测试，完成原准备要求并执行该关制作或服务操作
- **THEN** 所需工位和材料可通过现有操作及采购路径获得，动作由原规则裁决，不因缺少虚构的前序存档而卡住

#### Scenario: 功能菜单使用有限物资
- **WHEN** 用户进入一个制作功能场景并使用原料
- **THEN** 物品与份数按原规则消耗，测试没有自动补货、无限资源或 UI 直接改写结果

### Requirement: 测试进度不进入正式持久化链

系统 MUST 将测试运行标记为临时世界，不绑定正式保存、不覆盖或创建正式成功记录、不生成合作领取凭证，不提供导入、导出或有损替换操作。测试成功、换关、完成章节、重开和退出均不能改变既有正式记录或领取状态。正常章节与菜单试玩继续保留原保存语义。

#### Scenario: 已有正式记录时完成测试
- **WHEN** 已存在正式记录和合作领取状态，用户运行测试并经历成功结算、合法换关或终关完成后退出
- **THEN** 正式记录的槽位、修订和原业务内容保持原值，领取状态不变，也没有新增测试成功记录或凭证

#### Scenario: 测试后继续正常游戏
- **WHEN** 用户返回首页并明确继续原正式记录
- **THEN** 仍按该记录恢复原关链、布局和库存，测试选择、物资与分数不进入正常世界

### Requirement: 测试运行可重开并明确返回

系统 SHALL 持续显示测试运行标识，在原菜单中提供重开当前测试、返回测试列表和返回主菜单。重开须先完整退役旧运行，再以同一有效条目创建新运行，清除手持物、作业、顾客、订单及本轮分数；返回列表保留应用内上次选择。重复点击、退出期间加载和迟到回调不能同时建立多个世界或复活旧视图。

#### Scenario: 加工中重开后再操作
- **WHEN** 测试中存在手持物、加工和订单，用户明确重开，再使用新世界的原合法操作
- **THEN** 新运行从条目初态开始，旧作业和回调不影响新关，一次新操作只提交一次

#### Scenario: 返回列表与退出应用
- **WHEN** 用户返回测试列表后再次进入上次条目，随后结束本次应用
- **THEN** 当前应用内保留选择，旧世界已释放；应用结束不保存测试世界，也不承诺下次恢复测试进度

### Requirement: 测试使用真实操作与单一裁决

系统 MUST 复用正常单人玩法的操作、配方验证、生产权限、暂停、营业与收尾流程；测试选择、说明和导航不成为第二份世界状态。只有新建测试起点具有有限初始化差异，不因测试身份放宽运行中的动作条件；单人测试不创建网络监听或向本机发送 UDP。

#### Scenario: 测试中的合法操作与拒绝
- **WHEN** 用户在测试中分别执行一次合法拿放和一次原规则不允许的操作
- **THEN** 合法结果与拒绝均来自原裁决，物品不因界面显示发生额外变化
