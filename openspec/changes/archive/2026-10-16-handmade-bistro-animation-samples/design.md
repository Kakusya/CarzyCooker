# Design

## Context

见 proposal.md。现有 `Art/CarzyCooker/export_art.py` 将模型渲染为 192×192 精灵；完整导出会写正式图集与布局代码。当前 UI／表现代码有其他会话未提交修改。

## Goals / Non-Goals

**Goals:** 提供手作小馆风格的可编辑源、透明逐帧素材、完整帧元数据和实际可播放预览。

**Non-Goals:** 不接入运行时、不修改现有源／图集／Prefab／HUD，不操作共享 Editor，不改变 ET owner 树或消息。本批仅是表现资产交接，无新的 Fiber／Scene／状态权威。

## Decisions

- **独立导出源和目标**：新增 HandmadeBistro 目录，所有模型、临时渲染、成品与预览只写该目录。保留现有生产导出器。相比直接覆盖正式图集，这允许其他会话继续工作。
- **原生模型生成帧**：延续 Blender 建模与渲染方式，用同一模型连续姿态取样，避免逐张重画导致外观漂移。每个角色动作四方向各八帧，192×192；环境仍用静态资产。
- **内容分层**：空碗／锅／杯与液面、蒸汽分离；递餐动作不自带业务物品。预览组合食物只是展示，不构成已提交玩法状态。
- **离线预览**：本地 HTML 使用实际 PNG 表切帧，提供播放、暂停、逐帧、方向和速度控制；浏览器直接打开，无监听端口或额外服务。
- **交接格式**：PNG 单帧及精灵表、CSV 元数据（尺寸、顺序、帧率、循环、锚点），保留 Blender 工程与生成源。现有游戏不自动消费新帧表，后续按投影绑定。

## Risks / Trade-offs

- 帧间跳动或裁边 → 固定相机、固定脚底与容器中心，导出时检查 alpha 范围及帧差异；人工检查代表帧与循环。
- 新资产被误当正式版本 → README 与预览标明离线样板；不写 Unity/Assets。
- 只靠静态纹理无法判断动作 → 实际播放并检查暂停／逐帧，记录原始输出。
- 材质细节在小图中丢失 → 对照 192 原尺寸和放大图，优先剪影、局部高光与色块。

## Migration Plan

本轮无运行时迁移。正式接入需结合对方最新代码安排图集与姿态映射，然后执行相应 UTF 和真实入口验证。回退本次离线样板不会影响游戏。
