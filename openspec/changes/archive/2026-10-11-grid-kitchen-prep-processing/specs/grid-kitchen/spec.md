# Spec Delta

## MODIFIED Requirements

### Requirement: 两种目标入口与自动接近

场景目标点击和 UI 对应目标选择 SHALL 根据相同状态直接提交同一种默认动作，无须第二次确认。默认动作须识别普通拿放、兼容容器添加及切配台的开始／继续／本人停止；手持碗作业和暂停材料的显式拿取按钮也直接发起相应动作。台面动作仅能从上、下、左、右相邻格操作；非相邻点击自动前往一个可达四邻格，自动朝向目标后执行一次。没有合法接近位置时返回失败，不能隔格或斜向操作。

#### Scenario: 点击远处台面
- **WHEN** 玩家从远处点击可接近台面，默认动作仍合法
- **THEN** 自动寻路到可操作四邻格、转向并执行一次，无须再次点击

#### Scenario: 两种入口在相邻格操作
- **WHEN** 同样状态的玩家分别通过场景点击或 UI 选择相邻台面
- **THEN** 两种入口得到相同动作和结果，不要求事先手动调整朝向

#### Scenario: 斜邻位置不是可操作位置
- **WHEN** 玩家与台面仅为斜向相邻
- **THEN** 先到合法四邻格才执行；四邻格均不可达时明确失败，不直接交互

#### Scenario: 两种入口添加或开始切配
- **WHEN** 持鸡蛋玩家选择有合法空碗的台面，或空手玩家选择有未完成番茄的空闲切配台
- **THEN** 场景和 HUD 分别发起相同的添加或开始／继续切配动作，不要求额外确认，也不替换成拿取目标物品

### Requirement: 默认动作执行前再校验

默认动作 MUST 根据发起意图时已确认的目标、动作和相关源／目标物品身份确定，接近后由 Host 再核对位置、手槽、目标物品、容量、兼容和作业资格。针对已有作业的操作须核对当前作业身份与执行者。条件变化时明确拒绝，不悄悄改为另一种动作；验证失败不部分转移物品或重置进度。一次意图只执行一次。

#### Scenario: 接近期间物品被拿走
- **WHEN** 玩家发起拿取后，目标物品在到达前被队友取走
- **THEN** 原意图失败，玩家手槽不取得替代物，目标状态不发生额外变化

#### Scenario: 两人争取同一物品
- **WHEN** 两名玩家均请求从同一台面拿取同一个物品
- **THEN** 只有首个合法提交取得物品，另一个请求明确失败，世界中不产生该物品副本

#### Scenario: 接近期间目标碗变化
- **WHEN** 玩家发起向某空碗添加鸡蛋后，队友替换了该碗或先占用了它的容量
- **THEN** 原添加请求明确拒绝，鸡蛋仍在原手槽，不改做放置、交换或向新碗添加

### Requirement: 普通物品交接与位置唯一

普通手槽和台面 MUST 各最多放一个外层物品。空手可拿取目标物品，持物可放入空台面；持物面对有物台面时仅允许明确选定的兼容容器添加，其他情况拒绝，不默认交换。添加须通过容器兼容、容量及作业锁定校验，成功后源材料只位于容器内部。物品保留稳定身份，任一时刻仅处于一个位置；容器内容随容器移动，不因拿放复制或散出。

#### Scenario: 用台面交接
- **WHEN** 甲把手中物品放到空台面，乙随后合法拿取
- **THEN** 同一物品依次从甲手槽转到台面再到乙手槽，每次提交后只在一个位置

#### Scenario: 满手或满台面
- **WHEN** 玩家持有物品并试图操作已有物品的台面，且不是合法兼容容器添加
- **THEN** 返回容量或动作不合法结果，手中物品和台面物品均保持原位置

#### Scenario: 持物添加到台面容器
- **WHEN** 玩家手持鸡蛋并合法添加到台面上的空碗
- **THEN** 台面仍仅持有同一碗，手槽清空，鸡蛋仅成为该碗内容，不在台面新增第二个外层物品
