# Spec Delta

## Purpose

为合作厨房提供真实材料、容器内容与可接续的手工加工，使玩家能够制作并交接番茄蛋花汤所需的半成品。本轮仅覆盖番茄切块和手持碗打蛋，使用临时地图与单电脑会话，不代表煮汤、订单、正式餐厅或存档已经成立。

## ADDED Requirements

### Requirement: 最小材料与手工配方定义

系统 SHALL 根据明确物品定义识别番茄、番茄块、鸡蛋、蛋液和碗，根据手工配方定义匹配输入、作业方式、耗时及输出，不以显示名字推断类型。临时地图 MUST 提供两种作业所需的初始物资和切配台；必需定义缺失或引用无效须明确初始化失败，不使用占位内容伪装可加工。

#### Scenario: 普通入口提供可加工物资
- **WHEN** 玩家从普通 Launcher 进入新的 Solo 样机
- **THEN** 可以取得番茄、鸡蛋和空碗，找到切配台，碗中没有“占位食材”，两种手工配方均可按实际条件使用

#### Scenario: 必需定义缺失
- **WHEN** 本轮所需物品或配方定义缺失或引用无效
- **THEN** 明确报告初始化失败，不报告加工就绪，也不替换为硬编码同名材料

### Requirement: 真实容器内容与完整添加

材料 MUST 保留独立运行身份和唯一位置。将手中材料放入台面容器前，系统须完整校验源物品、目标容器、可达位置、兼容、容量和作业锁定，成功才同时清空源手槽并建立容器内容关系。容器搬运和交接须携带同一内容，拒绝不得消费、复制或部分转移材料；本轮不接受容器套容器。

#### Scenario: 鸡蛋入碗后搬走
- **WHEN** 玩家向合法空碗添加手中鸡蛋，随后拿走该碗并交到另一台面
- **THEN** 鸡蛋离开原手槽并仅在同一碗中，碗和鸡蛋各自身份保持，原台面不留下另一份内容

#### Scenario: 添加条件不成立
- **WHEN** 添加使用错误材料、满碗、失效目标或正在加工的目标
- **THEN** 明确拒绝，源材料、手槽、目标碗及其内容保持原状态，不自动交换或换目标

### Requirement: 手工开始与统一进度

手工作业 MUST 通过一次明确点击开始或继续，无须持续长按。成功开始仅建立执行资格，后续由 Host 业务 Tick 推进；客户端、动画和心跳不能增加进度。系统须将“开始已成功”与“加工已经完成”区分，尚未到达所需耗时不能提前生成可拿取成果。

#### Scenario: 点击开始后持续推进
- **WHEN** 玩家合法开始切配或手持打蛋，保持有效作业条件
- **THEN** 无须继续按住按钮，进度按业务 Tick 增加，到达耗时前仍显示加工中且没有完成产物

### Requirement: 单工作者与暂停接续

每项手工作业 MUST 同时只有一个有效执行者，每名玩家同刻最多参与一项手工作业，一个工位同刻最多推进一项作业。停止、移动或失去作业依赖须释放认领并保留已提交进度；合法队友可从该进度继续。重复开始或多人操作不能重置进度、重复作业或增加推进速度。

#### Scenario: 移动后由队友继续切配
- **WHEN** 甲切配到一半后点击地面移动，乙合法接手原材料
- **THEN** 甲开始移动前暂停作业，进度保持，乙从原进度继续，甲不再推进同一作业

#### Scenario: 显式停止和争抢认领
- **WHEN** 甲合法停止作业，乙接续后甲或另一玩家再次尝试认领
- **THEN** 停止期间进度不增加，乙为唯一执行者，后来的冲突请求明确拒绝且不改变原进度

### Requirement: 切配生成新半成品

切番茄 MUST 在合法切配台上进行，完成时一次性消费原番茄并创建新的番茄块物品，输出占用原切配台的单槽。未完成时保留输入和作业进度；暂停材料可搬运至合法切配台再继续。完成后玩家或队友可正常拿放番茄块，不能再次领取同一次加工的第二份输出。

#### Scenario: 完成切配并交接
- **WHEN** 合法切配达到所需进度，队友拿走番茄块
- **THEN** 原番茄已消费，番茄块使用新的运行身份且只存在一份，队友可将它放到普通交接台

#### Scenario: 搬运暂停的切配材料
- **WHEN** 玩家停止切配，显式拿取并搬运原材料后在合法切配台继续
- **THEN** 原材料和作业身份保持，从已有进度继续，不因搬运重置或提前形成番茄块

### Requirement: 手持碗打蛋与容器复用

玩家 MUST 能在手持含合法鸡蛋的碗时开始打蛋，无须占用工位。完成时消费碗中的原鸡蛋并生成独立蛋液物品，蛋液仍属于同一碗；碗的身份和外部位置不变。暂停后交给另一玩家仍能接续，不因换人复制蛋液或重置进度。

#### Scenario: 同一碗打蛋并交接
- **WHEN** 玩家手持含鸡蛋碗完成打蛋，再放到交接台供队友拿取
- **THEN** 同一碗携带一份新身份蛋液，原鸡蛋已消费，不需要第二个制作碗或打蛋工位

#### Scenario: 交接尚未完成的打蛋
- **WHEN** 甲停止打蛋并放下碗，乙拿碗后继续
- **THEN** 原碗、原输入与已有进度保持，只有乙合法认领后才恢复推进

### Requirement: 作业与角色退出分离

成员断线或已提交 Leave MUST 立即失去作业资格，保留已有材料和进度并释放认领；手持容器随原规则在最后提交格落物，内容不能散出或丢失，合法队友可拾取并接续。重复收尾不得重复产物。整体退出须停止本轮作业并释放临时世界，旧请求或结果不能写入下一轮。

#### Scenario: 打蛋中失联后队友接续
- **WHEN** 持碗打蛋的成员失联，队友来到落物同格并拾取该碗
- **THEN** 失联后原成员不再增加进度，碗及鸡蛋内容和进度保留，队友可合法继续，重复失联收尾不多落一个碗

#### Scenario: 整轮停止后开始新样机
- **WHEN** 旧世界存在未完成作业时整体退出，再进入新世界
- **THEN** 新世界使用本轮初始物资，旧作业、旧命令和迟到答复不能创建或完成新世界的加工

### Requirement: 本地与本机联机使用同一加工事实

Solo、Host 本地玩家和本机 KCP 玩家 MUST 经过相同裁决与提交规则。客户端须独立保存同一世界版本的材料、容器和作业投影，消息回收不损坏投影；重复业务编号不重复添加或产物，旧世界或失效绑定数据不得应用。本轮协议版本为 3，旧版本须明确拒绝。

#### Scenario: 同电脑合作与重复指令
- **WHEN** 同一电脑上的本地及真实 KCP 客户端分工备料，并重放已接收的合法添加或开始指令
- **THEN** 两端观察相同内容和进度，材料只添加一次、加工只完成一次，各端投影不共享 Host 的可变状态

#### Scenario: 旧协议或旧数据到达
- **WHEN** 版本 2 的接入／命令或旧世界、失效绑定的数据到达
- **THEN** 明确拒绝不兼容接入或命令，旧数据不改变当前材料、进度或执行资格

### Requirement: 可读作业提示与受管输入

地图和 HUD SHALL 显示可识别的工位、物品、碗中内容、作业进度与加工／暂停／完成状态，提供当前合法的开始、停止、继续及拿放动作。拒绝应说明材料、容量、目标变化或工作占用原因；UI 点击不得同时提交地面移动。关闭重开后按钮不得叠加提交，同一点击只产生一次意图。

#### Scenario: 从普通 Launcher 完成备料
- **WHEN** 玩家通过场景目标和 HUD 完成切配、鸡蛋入碗、打蛋及半成品交接
- **THEN** 能辨认工位和内容，观察进行中、停止及完成，开始成功不误显示为成品已完成，HUD 操作不触发地图穿透移动

#### Scenario: 关闭后重新进入
- **WHEN** 受管界面随本轮退出关闭，之后新一轮重新打开并点击动作
- **THEN** 旧按钮订阅及结果不影响本轮，该次点击只提交一个本轮意图
