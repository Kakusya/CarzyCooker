# Spec Delta

## ADDED Requirements

### Requirement: 联机前厅个人操作共同裁决

Host 本地与远端成员 SHALL 能在当前关按相同资格询问、交付、清桌、洗碗和取回餐具。成员身份来自可信连接，实际到位后重验顾客、订单、工作与物品；旧目标、错菜、重复交付或失效成员不能消费实物或重复计分。

#### Scenario: 远端交付后原碗回收
- **WHEN** Client 合法交付真实碗装汤，顾客吃完离席，合法工作者依次清桌和洗碗
- **THEN** 仅交付计分一次，同一碗经过餐桌、脏池、干净池后可再取得，两端观察相同身份与卫生状态

#### Scenario: 桌位换客后旧交付迟到
- **WHEN** 同桌已换顾客，远端旧交付到达
- **THEN** 拒绝旧请求，保留原手持菜品与内容，不完成新订单或改变得分

### Requirement: 联机玩家和伙伴共享单一工作认领

前厅工作 MUST 同时最多有一名合法执行者。Host、Client 和伙伴通过既有工作裁决认领，玩家停止或断线后保留已开始进度并释放其资格，其他合法执行者可以接续；重复收尾不能重置或完成第二份工作。

#### Scenario: 玩家与伙伴同时认领
- **WHEN** 两名玩家或玩家与伙伴同时请求同一询问／洗碗工作
- **THEN** 只成立一个执行者，按真实到位和业务时间推进一次，其他请求不改原工作进度

#### Scenario: 远端断线后接续
- **WHEN** Client 已开始洗碗后断线，Host 或伙伴接手
- **THEN** 旧执行者失效，从原进度继续，同一餐具只洗净一次，其他成员仍能通信

### Requirement: 联机前厅投影与操作目标一致

两端 MUST 在同一世界、关代次与提交版本下观察顾客、订单、餐桌、餐具池、伙伴、工作与得分。界面只提交已确认的真实目标，不建立本端顾客或工作权威；通知回收与旧 UI 回调不得改变新状态或多发请求。

#### Scenario: 当前订单在通知回收后仍有效
- **WHEN** 远端收到订单与工作状态且原通知对象被回收
- **THEN** 已安装数据独立有效，界面能提交一次当前目标请求；旧界面的回调不能替代当前身份
