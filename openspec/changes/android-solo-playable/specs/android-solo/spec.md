# Spec Delta

## Purpose

在保留现有框架与热更新结构的前提下，把已选单机餐厅功能交付到真实 Android 设备，明确触控、切后台暂停和本平台成功检查点恢复的行为，使手机可玩性有独立证据而不依赖 Editor 模拟。

## ADDED Requirements

### Requirement: 触控意图与既有操作一致
Android Solo SHALL 支持单指点击和拖动的既有合法操作；拖动不附带点击，界面关闭重开不重复提交，未就绪或暂停时保留原输入限制。

#### Scenario: 拖动后抬手
- **WHEN** 玩家完成一次有效拖动并抬手
- **THEN** 只产生该拖动对应意图，不追加拾取、交付或其他点击动作

### Requirement: 后台冻结且前台手动继续
应用进入后台 MUST 暂停业务进度；消息泵若已被挂起，恢复时必须先落实暂停再允许业务步。不得补算后台经过的业务时间，返回前台保持暂停，玩家显式继续后才恢复经营。

#### Scenario: 加工中切后台并回来
- **WHEN** 玩家在加工和来客计时期间切后台，等待后返回
- **THEN** 加工、来客和订单时间未按后台时长推进，界面保持暂停，手动继续从原进度进行

### Requirement: Android 检查点平台隔离
Android 成功检查点 MUST 使用明确 Android 平台身份和本平台存储位置；不得接受 PC 档或隐式导入跨平台文件。失败保留原有效文件，不显示保存成功。

#### Scenario: 在 Android 读取 PC 标识记录
- **WHEN** 读取输入的平台标识为 PC
- **THEN** 明确拒绝且不改写输入或本机已有记录

### Requirement: 强杀仅恢复最后成功检查点
进程被终止后 SHALL 通过正常选档恢复最后已成功发布的检查点或查看完成记录；不得声称未结算临时进度已保存，完成记录不能创建下一关。

#### Scenario: 已存档后加工中被终止
- **WHEN** 玩家已有成功检查点，随后在下一关加工中被系统终止
- **THEN** 重启只恢复成功检查点中的状态，不虚构后续未保存加工或订单进度

### Requirement: 真机交付证据独立
Android 交付 MUST 记录实际构建、热更与 AOT 结果以及真实设备上的输入、后台、三关和重启恢复结果。Editor 显示成功或包目录存在不能替代，未验证设备范围须明确。

#### Scenario: Editor 通过但 AOT 失败
- **WHEN** Editor 相关行为通过而实际平台 AOT 或运行失败
- **THEN** 报告 Android 未完成，保留实际返回码及日志，不关闭热更来冒充原目标成功
