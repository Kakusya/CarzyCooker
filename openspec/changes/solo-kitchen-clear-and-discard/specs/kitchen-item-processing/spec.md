# Spec Delta

## ADDED Requirements

### Requirement: 清理必须交互对应设施

清空和丢弃 MUST 以实际水池或垃圾桶为目标，在合法四邻操作位置执行。远处选择设施可自动接近后执行一次；目标不可达、设施缺失或能力不匹配须拒绝。不允许在手持物、普通台面或任意地面位置直接删除内容。

#### Scenario: 远处选择设施与原地清空

- **WHEN** 持物玩家从远处选择合法清理设施，或尝试不指定对应设施直接清空
- **THEN** 前者到位后才处理，后者拒绝，行走途中不会提前删除物品

### Requirement: 液体只在水池排放

系统 MUST 在有排液能力的水池处理定义为液体的内容和已完成液体批次，消费对应内容及剩余份数，保留原容器身份、持有位置和脏净状态。固体不能通过水池销毁；完成批次按其成品形态核对，而非按留存输入的种类误判。

#### Scenario: 把剩汤带到水池

- **WHEN** 玩家持未锁定的剩汤锅或汤碗到水池合法倒液
- **THEN** 剩余汤/批次被处理，同一锅或碗仍在原手槽，材料不回库，容器不自动洗净

#### Scenario: 把固体倒进水池

- **WHEN** 玩家持番茄块或盘内烤面包向水池请求清理
- **THEN** 明确拒绝，原物件、容器内容和位置不变

### Requirement: 固体垃圾只向垃圾桶倾倒

系统 MUST 只在垃圾桶销毁定义允许丢弃的固体普通物件，或清空固体容器内容。容器内容被处理时保留容器；锅、碗、盘和设备不得被当作普通固体垃圾整体销毁。空包装按其定义获准后也须投入垃圾桶，不退款、回库、加分或形成产物。

#### Scenario: 固体容器内容与普通物件

- **WHEN** 玩家把盘中烤面包或手持番茄块送到垃圾桶
- **THEN** 前者只处理内容并保留盘，后者消费指定普通物件；其它物品和设备不变

### Requirement: 水池接水形成真实内容

系统 SHALL 在具备接水能力的水池，向干净、空且定义兼容的实际容器提供配置的一份水。水具有自己的物品身份并属于该容器，容量、占用和源/目标身份须完整校验。满容器、脏容器或不可达拒绝，接水不顺带清空或洗净旧内容。

#### Scenario: 空碗接水与满碗拒绝

- **WHEN** 玩家持合法空碗在水池接水，随后对满碗再次接水
- **THEN** 首次形成一个属于原碗的水物件，第二次拒绝且不复制、替换或删除内容

### Requirement: 设施处理仍保护加工与身份

处理前 MUST 核对当前关/绑定、源物件/内容或批次、目的设施、可达位置及有效占用。加工锁定或仍有执行者的输入不能处理；合法暂停作业须完整收尾相关引用。嵌套容器不连带销毁，重复请求不重复处理，目标变化拒绝且不改做另一动作。

#### Scenario: 接近期间变化或输入锁定

- **WHEN** 接近设施途中源内容/设施发生变化，或输入仍在煮制/烘烤中锁定
- **THEN** 明确拒绝且保持物品/加工；不会改为原地清空或处理替代物

### Requirement: UI 显示设施操作而非随身删除

场景与 HUD SHALL 指向同一真实设施并按当前状态提供接水、倒液或投垃圾动作，反馈接收/接近/最终结果。未到位不显示清理成功；关闭重开一次点击只提交一次当前身份请求，旧关/旧 owner 回调无效。

#### Scenario: HUD 选择水池

- **WHEN** 玩家在 HUD 选择水池倒液并关闭重开界面
- **THEN** 仍需实际走到该水池才能处理，重开不重复倾倒或额外清空
