# automated-testing Specification

## Purpose

提供 CarzyCooker 自动测试的项目发现、明确范围执行和真实结果报告契约。只使用现有 Unity CLI/Pipeline 与 UTF，保留原始输出，空集和未运行不冒充通过，避免覆盖用户现场或复制参考专属玩法与证据机制。

## Requirements

### Requirement: 精确工程与显式测试范围

测试入口 MUST 核对实例工程、编辑器就绪状态及当前命令接口；默认只发现测试。执行必须明确选择模式和过滤范围，不能修改用户正在运行的 Play/测试作业。

#### Scenario: 执行指定测试
- **WHEN** 用户已授权某一测试且工程 ready、停止 Play、无运行作业
- **THEN** 在发现列表中确认匹配项后启动一个异步作业，并始终显式指定本工程路径

#### Scenario: 存在运行作业或工程不符
- **WHEN** 当前实例工程不符、正在 Play/编译或已有测试运行
- **THEN** 拒绝启动，不自动停止、取消或转向其他工程

### Requirement: 终态与失败真实报告

编排器 MUST 解析结构化返回值而非查找成功字符串；等待终态和 Player 停止，区分通过、失败、编排异常、跳过和未运行。空集、全跳过、未知状态、丢失输出及超时不得算作通过。修复后发起新运行，不续跑或改写失败结果。

#### Scenario: 测试失败
- **WHEN** 终态结果包含失败或 inconclusive
- **THEN** 返回非零退出码并输出失败消息与堆栈；Console 新错误也导致失败

#### Scenario: 空集或全跳过
- **WHEN** 无匹配测试或没有实际通过的用例
- **THEN** 报告 NotRun 或 Skipped 和非零退出码，而不是全绿

#### Scenario: 超时与域重载
- **WHEN** 短暂不可达在等待窗口内恢复
- **THEN** 继续只轮询当前作业；超过总时限则报告异常和可能仍在运行，不取消或启动第二作业

### Requirement: 原始结果与 Console 完整性

测试工具 MUST 直接报告即时结果及原日志位置，不新建 JSON 证据包、状态副本或 hash 清单，不搬走、清除或覆写原始结果。Console 会话变化或缓冲丢失必须报告覆盖缺口，不以日志缺失证明成功。

#### Scenario: 检查本轮错误
- **WHEN** Player 停止且当前 Console 游标完整
- **THEN** 使用同会话游标读取本轮新增 Error/Exception/Assert，保留次数、消息与项目栈帧，存量错误单独说明

#### Scenario: Console 会话重置
- **WHEN** 域重载导致会话变化或缓冲丢失
- **THEN** 不把截断日志当完整验证；可见错误报失败，无法确认完整覆盖报编排异常

### Requirement: 功能任务逐项运行验收

功能任务 MUST 在标记完成前实际运行各功能验收点，以 UTF 验证可自动断言的行为；用例不足时补充并执行。启动、UI、输入或联机任务还 SHALL 通过真实入口确认对应功能。验收记录须对应任务、功能与运行结果；实现及验收条件未变时可复用适用的有效结果。必需功能失败或未运行时不得报告验收完成；用户明确接受有限交付时保留未验证项。纯文档任务记录正文、格式与引用检查。

#### Scenario: 新增功能准备完成任务
- **WHEN** 新增或改变的功能任务准备标记完成
- **THEN** 逐项对应验收点与已执行 UTF／真实入口结果，用例有实际行为断言，未运行功能不被其他用例或编译结果替代

#### Scenario: 复用已有验收结果
- **WHEN** 已有通过结果完整覆盖当前未变的实现及验收条件
- **THEN** 记录对应功能与原结果来源，可复用而不重复运行；新增或改变行为及缺少证据的验收点继续补验

#### Scenario: 必需功能未验收
- **WHEN** 必需功能失败、未运行、被跳过、匹配空集、超时或缺少完整输出
- **THEN** 相关功能验收和任务保持未完成，明确报告缺口；用户接受有限交付时仍不将未验证功能称为已验收
