# grid-kitchen Specification

## Purpose

为竖屏合作厨房提供可判断的格子空间、点选移动和相邻交接，让单机与联网玩家观察一致的操作结果。首轮以固定临时地图验证行走、物品位置与断线收尾，不代表正式餐厅、存档或完整烹饪已经实施。

## Requirements

### Requirement: 固定地图与竖屏显示

系统 SHALL 提供使用 2D 场景和角色的固定示例地图，采用正对地图边的 45° 俯视效果及正交显示。厨房在初始竖屏视野内完整可见，前厅位于下方，纵向拖动移动整张地图的视野；地面常驻淡格线，点选时高亮目标和可用路径。

#### Scenario: 查看厨房与前厅
- **WHEN** 玩家进入样机并向下查看前厅
- **THEN** 初始可以看全厨房，拖动后看到下方前厅，厨房随同一地图视野移动；同尺寸格子的显示大小不因远近改变，格子不呈水平旋转 45° 的菱形

#### Scenario: 点选地面
- **WHEN** 玩家点击有效地面格
- **THEN** 显示目标高亮及已知路径；高亮本身不把角色位置改为已到达

### Requirement: 点击与拖动区分

地图输入 SHALL 将一次手势区分为点击或纵向拖动。已经判为拖动的手势不得在松开时再提交行走或目标交互；UI 消费的点击不得同时穿透成地面命令。

#### Scenario: 滑动查看前厅
- **WHEN** 玩家拖动地图后松开手指
- **THEN** 只改变本端视野，不移动角色、不提交物品动作

#### Scenario: 点击 UI 目标
- **WHEN** 玩家点击 UI 中一个可操作目标
- **THEN** 只产生该目标的一次默认动作意图，不同时提交 UI 下方地面行走

### Requirement: 四方向自动寻路

系统 MUST 仅使用上下左右相邻格移动。点击远处可走格后自动寻找可达路线，逐格推进；固定障碍和台面占格不可通行，落物不阻挡路线。越界、不可走或不可达目标必须给出明确结果，不把角色传送到目标。

#### Scenario: 绕开台面到达远格
- **WHEN** 玩家点击需绕过台面的可达地面格
- **THEN** 角色沿可走四邻格路线到达，转角不斜穿障碍

#### Scenario: 不可达目标
- **WHEN** 玩家点击被固定障碍隔开的地面格
- **THEN** 返回不可达结果，保留当前已提交位置，不执行越墙或传送

### Requirement: 移动中替换目标

角色移动中接受新目的地或目标交互时 MUST 先完成已经开始的当前一步，再从该格替换后续路线。较新的意图替换尚未执行的旧目标；不得在两格之间停下、回跳或让被替换的交互继续执行。

#### Scenario: 当前一步中改去另一个格
- **WHEN** 角色从 A 格向 B 格行走时收到新的 C 格目的地
- **THEN** 先完成 A 到 B，再从 B 规划去 C 的路线，不继续原目的地的后续步骤

#### Scenario: 取消尚未到达的台面动作
- **WHEN** 自动接近台面期间玩家重新点击地面
- **THEN** 完成当前一步后改走新路线，旧台面的默认动作不执行

### Requirement: 穿行与停驻容量

玩家 MUST 能穿过其他玩家；每格最多两名场上角色停驻，经过不占停驻名额。目的格满员时，角色在路线最后一个可停驻格等待，保留目的地；空位出现后继续。该容量不得解释为整局最多两名成员。

#### Scenario: 穿过有玩家的格
- **WHEN** 路线经过已有两名停驻玩家的格，后续目的格可停驻
- **THEN** 角色可以经过该格，不因玩家位置把格子当成固定障碍

#### Scenario: 第三人到达满员目标
- **WHEN** 两人已经停在目标格，第三人也以该格为目的地
- **THEN** 第三人等待在最后可停驻格，不增加目标格第三名停驻者；其中一人离开后继续前进

### Requirement: 两种目标入口与自动接近

场景目标点击和 UI 目标选择 SHALL 直接提交同一种默认动作，无须第二次确认。普通台面仅能从上、下、左、右相邻格操作；非相邻点击自动前往一个可达四邻格，自动朝向目标后执行一次。没有合法接近位置时返回失败，不能隔格或斜向操作。

#### Scenario: 点击远处台面
- **WHEN** 玩家从远处点击可接近台面，默认动作仍合法
- **THEN** 自动寻路到可操作四邻格、转向并执行一次，无须再次点击

#### Scenario: 两种入口在相邻格操作
- **WHEN** 同样状态的玩家分别通过场景点击或 UI 选择相邻台面
- **THEN** 两种入口得到相同动作和结果，不要求事先手动调整朝向

#### Scenario: 斜邻位置不是可操作位置
- **WHEN** 玩家与台面仅为斜向相邻
- **THEN** 先到合法四邻格才执行；四邻格均不可达时明确失败，不直接交互

### Requirement: 默认动作执行前再校验

默认动作 MUST 根据发起意图时已确认的目标和动作条件确定，接近后由 Host 再核对位置、手槽、目标物品和台面容量。条件变化时明确拒绝，不悄悄改为另一种动作；验证失败不部分转移物品。一次意图只执行一次。

#### Scenario: 接近期间物品被拿走
- **WHEN** 玩家发起拿取后，目标物品在到达前被队友取走
- **THEN** 原意图失败，玩家手槽不取得替代物，目标状态不发生额外变化

#### Scenario: 两人争取同一物品
- **WHEN** 两名玩家均请求从同一台面拿取同一个物品
- **THEN** 只有首个合法提交取得物品，另一个请求明确失败，世界中不产生该物品副本

### Requirement: 普通物品交接与位置唯一

普通手槽和台面 MUST 各最多放一个物品。空手可拿取目标物品，持物可放入空台面；持物面对有物台面时拒绝，不默认交换。物品保留稳定身份，任一时刻仅处于一个位置；容器内容随容器移动，不因拿放复制或散出。

#### Scenario: 用台面交接
- **WHEN** 甲把手中物品放到空台面，乙随后合法拿取
- **THEN** 同一物品依次从甲手槽转到台面再到乙手槽，每次提交后只在一个位置

#### Scenario: 满手或满台面
- **WHEN** 玩家持有物品并试图操作已有物品的台面
- **THEN** 返回容量或动作不合法结果，手中物品和台面物品均保持原位置

### Requirement: 断线角色移除与手持物落地

意外断线 MUST 使原绑定立即失去命令资格，并由 Host 移除对应场上角色；手持物在角色最后提交的格留下一个可拾取物品。行走插值位置不能决定落点，已经提交的动作不回滚，未提交的旧绑定动作不得继续执行；离线逻辑成员保留不等于角色仍留场。

#### Scenario: 行走中断线
- **WHEN** 持物角色在两格之间的显示动画期间断线
- **THEN** 物品留在 Host 最后已提交的所在格，角色从场上移除，客户端显示位置不改变落点

#### Scenario: 重复收到断线收尾
- **WHEN** 同一角色的失联清理重复到达
- **THEN** 不再次落出相同手持物，不改变其他玩家角色和手槽

### Requirement: 独立落物与同格拾取

地面落物 SHALL 不占阻挡格或停驻名额。同格允许多个独立物品，玩家必须选择具体物品；只有站在同一格且手槽为空时才可拾取。相邻格、满手或已失效物品的请求必须拒绝；正常台面交互仍使用四邻规则。

#### Scenario: 同格存在多个物品
- **WHEN** 玩家站在有多个落物的格，选择其中一个有效物品
- **THEN** 仅该物品转入手槽，其余物品各自保留身份与位置，不合并成堆叠数量

#### Scenario: 从邻格或满手拾取
- **WHEN** 玩家从邻格请求拾取地面物品，或站在同格但已有手持物
- **THEN** 明确拒绝，地面物品和手槽不变化
