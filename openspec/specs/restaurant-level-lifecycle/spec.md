# restaurant-level-lifecycle Specification

## Purpose

定义单机餐厅从准备、营业到自然收尾与下一关的可观察流程，使持续厨房和当前关卡具有不同寿命。区分内存试玩与已发布的本机检查点，明确暂停、得分、实物承接、三关终点和技术退出。

## Requirements

### Requirement: 单机餐厅与关卡归属

餐厅 MUST 同时最多拥有一个当前 Level，持续厨房与 Level 分别归餐厅管理。角色、顾客、订单、前厅工作、营业计时、得分、成长和 buff 属于本关；厨房物品、工位和加工属于持续厨房。当前关结束不得顺带销毁需要承接的厨房状态。

#### Scenario: 保留半锅汤并结束本关
- **WHEN** 前厅已收口，厨房仍有剩余一份的完成锅与未完成加工
- **THEN** 本关可以结束，这些物品、份数和加工身份仍留在同一厨房

### Requirement: 准备营业与自然收尾

Level MUST 依次经历 Preparing、Operating、Draining、Completed。Preparing 允许合法备料和布局但不来客或交付；营业到时转收尾并停止新来客；既有顾客、行走、用餐、清桌和必要洗碗按真实进度排空后才完成，不强制完成未做服务，也不要求排空后厨。

#### Scenario: 营业时间到但仍在用餐和洗碗
- **WHEN** 营业结束时仍有顾客用餐或必要前厅工作
- **THEN** 进入收尾，停止新来客，继续实际工作到合法排空后成功

### Requirement: 暂停取消未执行动作并停钟

暂停 MUST 取消已接收但尚未提交的动作、尚未执行的后续路径与目标互动，并给取消结果；已开始的手工、自动加工和前厅工作保留进度，统一业务时间停止。进行中的当前一步保留已用时间，恢复后只完成该步，不恢复已取消目标。暂停中拒绝新业务动作，仍可接收恢复、退出及状态请求。

#### Scenario: 自动接近期间暂停
- **WHEN** 角色正在走当前一步，旧目标动作还未提交，玩家暂停
- **THEN** 旧目标被取消，当前步和已提交实物保持，恢复后完成当前步并停驻，不再执行旧目标互动

#### Scenario: 加工中暂停恢复
- **WHEN** 切配、煮汤或已开始询问进行中时暂停并等待后恢复
- **THEN** 暂停期间所有业务进度不变，本地恢复请求仍可答复，恢复后从原进度继续

### Requirement: 固定订单得分与零星成功

成功订单 MUST 按配置基础分只计一次，未满足订单计零且不倒扣。总分按递增关卡阈值显示零至三星，零星仍正常完成；非终关允许继续，明确终关按大关完成流程保存并返回选档。技术中断不能生成成功结算，不添加正常业务失败界面。

#### Scenario: 没有完成任何订单
- **WHEN** 顾客和前厅按规则排空，成功订单数为零
- **THEN** 显示零分及适用星级，不要求重试或强制补单；非终关允许继续，终关仍允许保存完成并返回选档

### Requirement: 内存换关保留实物而重置临时状态

非终关继续 MUST 在完成态仅安装一次新 Level；保留厨房物品、容器内容、剩余份数、工位布局和加工进度，禁止再次叠加初始物资。旧角色结束前先保留手持物于最后提交格；新角色使用新关出生位。顾客订单、计时得分、认领、成长、buff 和旧关权限重置，新关只读取新配置。明确终关不得通过继续创建新 Level，须采用完成记录流程。

#### Scenario: 重复继续与旧关动作
- **WHEN** 非终关完成态继续请求被重放，之后旧关动作迟到
- **THEN** 只安装一个新关，物资和批次不补满，旧关动作不能修改新关

#### Scenario: 终关旧继续请求
- **WHEN** 终关完成后收到继续或旧 UI 回调
- **THEN** 不创建下一关、不发装修、不重建初始物资，保留终关结果供完成记录流程处理

### Requirement: 单机试玩与持久检查点区分

系统 MUST 区分未选档的新开试玩与已成功发布的检查点。技术关闭释放当前餐厅，不将临时进度宣称为已保存；正式 Solo 继续须遵守成功检查点及保存失败阻止换关合同。首个三关大关的终关保存完成记录而不生成下一关，禁止用空保存冒充持久提交。

#### Scenario: 结束程序后重新开始
- **WHEN** 玩家关闭本轮运行并重新进入，选择新开而非继续有效检查点
- **THEN** 创建新的餐厅与初始物资，不显示刚才未发布的临时进度已经写盘；已有有效记录仍可单独选择

### Requirement: 联机营业自然收口

合作餐厅 MUST 沿用 Preparing、Operating、Draining、Completed 与原零星成功规则。Host 唯一业务时间驱动顾客、伙伴和工作，营业到点只停止来客；既有前厅实际排空才完成。Client 不得自行推进、提前完成或触发下一关。

#### Scenario: 双端等最后一个碗洗完
- **WHEN** 营业到点且最后一个脏碗仍在清洗
- **THEN** 两端保持 Draining 并观察实际进度，洗净及前厅排空后才显示同一结算，不靠远端帧数瞬间完成

#### Scenario: 零分自然完成
- **WHEN** 所有未满足订单按时离开且前厅排空
- **THEN** 两端显示同一零分结果，Host 可以继续，技术退出不能伪造此结果

### Requirement: 联机暂停不阻断控制通信

Host 暂停 MUST 取消各成员尚未执行的动作，冻结已开始加工、前厅工作、顾客及角色当前步；恢复与退出通信仍工作。恢复后接续已开始进度，但不恢复被取消的旧目标。远端无权自行恢复世界。

#### Scenario: 远端服务途中暂停
- **WHEN** Client 正在接近餐桌且已有另一项前厅工作进行，Host 暂停再恢复
- **THEN** 接近的目标被取消，当前步及已开始工作保留；两端恢复后不自动提交旧交付，控制请求仍有答复

### Requirement: 联机换关按当前身份重新就绪

Host 的合法 Continue MUST 只安装一个新关，保留同一厨房实物与批次，清理旧顾客、订单、工作、成长和 Buff；成员的新角色属于新关。客户端在取得匹配关身份、本人角色和状态前禁用输入，旧关高版本与旧结果不能覆盖新关。

#### Scenario: 重复继续及旧消息迟到
- **WHEN** Host 重放已成功 Continue，同时 Client 旧关请求和快照迟到
- **THEN** 只发生一次换关，物资不补满，旧请求被拒绝，旧快照不替代新关，双方从新角色就绪后继续操作
