# 游戏入口与合作房间

## Purpose

从普通 Launcher 在游戏内选择单机、创建合作或加入，合作成员可先集合，再由 Host 开启内存餐厅；关闭餐厅可以回同一房间。游戏内模式选择、房间停留、创建和退役餐厅。本能力区分已提交世界事实、持久记录和玩家操作，保证拒绝或中断有明确边界，并为后续有限内容扩展提供可观察的合同。

## Requirements

### Requirement: 游戏内选择与失败可返回

系统 SHALL 从普通 Launcher 提供单机、创建合作及显式目标加入入口；失败或取消回到可操作选择页，已有启动参数入口仍可使用。

#### Scenario: 加入失败再选择单机
- **WHEN** 显式加入目标拒绝或超时，玩家随后选择单机
- **THEN** 显示真实失败并收尾原连接，单机通过无监听本地入口进入，不被旧加入答复覆盖

### Requirement: 房间可以没有餐厅

合作 Match MUST 能在没有 RestaurantRuntime 时保留成员及有效连接；只有 Host 的合法开局提交才创建唯一餐厅。

#### Scenario: 先加入后开局
- **WHEN** 两端已经加入同一房间但尚未开局
- **THEN** 只显示房间和成员，不实例化厨房或开放地图动作；开局后按真实投影及本人角色就绪开放输入

### Requirement: 退役餐厅保留房间

关闭餐厅 MUST 使其旧动作与投影失效，并在完成业务收尾后释放餐厅和所属视图；Match、成员及通信仍可用于下一次开局。

#### Scenario: 返回房间后重开
- **WHEN** Host 关闭当前内存餐厅并再次开局
- **THEN** 新世界身份独立，旧消息无效，成员与连接不被重复创建或整体停止


### Requirement: 主入口任务导航可访问

系统 SHALL 提供以下入口行为：将开始游戏、继续记录、合作房间、合作进度和存档授权组织为清楚的入口分组，展示当前位置与返回目标；保留所有现有合法入口和显式启动参数。

#### Scenario: 主入口任务导航的正常使用
- **WHEN** 玩家从开始页进入合作进度，再返回并选择单机
- **THEN** 每次返回到明确父页，所有原合法入口仍可抵达；进入下级只改变页面，选择真实开局后才建立运行

### Requirement: 主入口任务导航保持事实与操作边界

系统 MUST 遵守以下边界：导航仅保存本轮页面选择；切换页面不创建餐厅、不加入房间、不触发文件操作。旧菜单／试验餐厅保留可访问入口，并与已交付内容章明确区分。

#### Scenario: 主入口任务导航的取消或状态变化
- **WHEN** 快速切换页面并触发旧页按钮，或带显式参数启动
- **THEN** 旧回调不执行，显式角色入口保持原语义，池化重开没有重复按钮

#### Scenario: 主入口任务导航关闭重开与旧回调
- **WHEN** 玩家关闭并重开本入口，随后旧页面回调或迟到结果到达
- **THEN** 页面只作用于当前有效上下文，原操作不因重开重复提交，旧结果不覆盖新选择，原合法入口仍可使用


### Requirement: 章节与新开餐厅预览可访问

系统 SHALL 提供以下入口行为：选择已交付章节或已有餐厅菜单后，先显示章节名称、实际关数、各关菜单、模式及保存语义，再明确开始；取消返回原列表。

#### Scenario: 章节与新开餐厅预览的正常使用
- **WHEN** 在单机或 Host 房间选择第二章，阅读菜单后确认开始
- **THEN** 预览和实际首关一致，确认只开一个餐厅，取消则不创建世界

### Requirement: 章节与新开餐厅预览保持事实与操作边界

系统 MUST 遵守以下边界：预览读取当前有效章／Level／Dish 定义，不创造新章节、难度或承诺平衡。Solo 保存选择与合作 Host 开局权限沿原规则；Client 可查看本端目录，但不暗示已同步为全房间共同选项。

#### Scenario: 章节与新开餐厅预览的取消或状态变化
- **WHEN** 在 Client 查看目录、取消预览，或持旧房间按钮确认
- **THEN** 查看不授予开局权，不修改房间；旧身份确认失效且不静默改开其他菜单

#### Scenario: 章节与新开餐厅预览关闭重开与旧回调
- **WHEN** 玩家关闭并重开本入口，随后旧页面回调或迟到结果到达
- **THEN** 页面只作用于当前有效上下文，原操作不因重开重复提交，旧结果不覆盖新选择，原合法入口仍可使用


### Requirement: 合作地址与连接帮助可访问

系统 SHALL 提供以下入口行为：按创建／加入阶段显示合法地址示例、当前实际监听地址、复制入口和可理解的连接／取消／重试说明；把回环地址的适用范围说明白。

#### Scenario: 合作地址与连接帮助的正常使用
- **WHEN** Host 创建房间后复制地址，Client 粘贴合法目标并加入
- **THEN** 复制值来自当前实例，连接进度与真实状态对应，一次确认只发起一次加入

### Requirement: 合作地址与连接帮助保持事实与操作边界

系统 MUST 遵守以下边界：只复制公开 endpoint；不展示凭证／密钥，不自动连网测试或扫描网卡，不改变现有显式 LAN 授权与地址校验。错误仅按实际校验／握手结果说明，不能猜测防火墙或声称公网可用。

#### Scenario: 合作地址与连接帮助的取消或状态变化
- **WHEN** 输入格式错误、回环地址用于异机或连接超时后取消
- **THEN** 页面解释实际适用范围和错误，取消收尾原尝试，旧答复不能影响重试或后续单机

#### Scenario: 合作地址与连接帮助关闭重开与旧回调
- **WHEN** 玩家关闭并重开本入口，随后旧页面回调或迟到结果到达
- **THEN** 页面只作用于当前有效上下文，原操作不因重开重复提交，旧结果不覆盖新选择，原合法入口仍可使用


### Requirement: 经营中离开与返回导航可访问

系统 SHALL 提供以下入口行为：提供按角色区分的离开入口及后果说明：Solo 返回模式、Client 离开本次运行、Host 仅关闭餐厅回房间与结束整个房间分别确认；确认前可取消。

#### Scenario: 经营中离开与返回导航的正常使用
- **WHEN** Solo 营业中取消离开后继续，Host 确认仅返回房间再开
- **THEN** 取消不影响运行，确认离开不补存档；Host 回原房间保留成员，新开世界独立

### Requirement: 经营中离开与返回导航保持事实与操作边界

系统 MUST 遵守以下边界：确认页不自动暂停或保存，需说明经营仍按原状态推进；不将技术离开伪造成功结算。Host 关闭餐厅保留 Match 和现有资格，正常结束整个 Match 沿原回执规则；提交中禁止重复且不把取消等待冒充撤销。

#### Scenario: 经营中离开与返回导航的取消或状态变化
- **WHEN** Client 持物离开、Host 结束整个 Match 或旧确认在新世界触发
- **THEN** 原成员落物／认领释放保持；关闭按原回执处理资格，旧确认不关新餐厅，失败显示实际状态

#### Scenario: 经营中离开与返回导航关闭重开与旧回调
- **WHEN** 玩家关闭并重开本入口，随后旧页面回调或迟到结果到达
- **THEN** 页面只作用于当前有效上下文，原操作不因重开重复提交，旧结果不覆盖新选择，原合法入口仍可使用
