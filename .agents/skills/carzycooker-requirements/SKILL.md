# 需求拷问

先加载 [openspec-explore](../openspec-explore/SKILL.md)，使用当前对话和已有探索结论作为输入；本技能在复杂/高风险需求的现状与候选方向已梳理后收敛决策。用户已经给定明确实施计划时，不从头拷问或重复确认已有决定。

读根 [AGENTS.md](../../../AGENTS.md)、[模块索引](../../../Docs/AI/module-index.md)、相关主规格与进行中 change。产品问题读 [长期目标](../../../long-term-goals.md)、[产品目标](../../../Docs/Product/README.md)、[待裁决](../../../Docs/Product/backlog.md)；框架问题读源码、参考与实际诊断，不把历史设计当已有能力。

问事实之前先查源码、表、规格、参考文档或工具输出，说明依据；只把产品选择、风险接受、偏好和真正缺失的决定交给用户。沿决策树依赖顺序收敛变化、直接消费者、当前/未来行为、owner 与范围外事项，不让用户重述可查事实。

按编号轮次覆盖必要决策，每题给基于证据的推荐及代价；用户要求一次一问时遵从该方式。只问会改变实施的问题，继续不依赖答案的研究。暂停命令、断线手持物和传输选型保持待裁决，未答不算批准；未知数值不借 fixture 填正式平衡。

没有待问的必要决定后，输出简洁决策账本：目标、范围/非范围、约束与证据、方案及考虑过的替代、接受的假设、边界/失败方式、可观察验收、剩余问题。保留已确认、授权补足、候选、待裁决的身份，不自动晋级。

不写业务代码，不自动创建 OpenSpec artifacts。账本结束后询问是否用它进入 `$openspec-propose`，等待用户确认；用户已明确授权提案时无需重复确认。拒绝或停止时不创建产物，澄清问题的答案也不等于实施授权。

新工具先提交用途、必要性、依赖、文件改动与验收再审批。探索不授权编辑器、联网、打包、端口或新测试管线，不创建状态副本、JSON 证据或额外脚本替代需求决定。
